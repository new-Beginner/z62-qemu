# r15：同次原厂 index3 启动 API 局部合同

目标：只在可追溯 r13 新模型上，用原始 Z6II C1.70 主从自然执行，接续同次 index3 API 输入→发布帧→原返回 POP→实际首次任务入口。返回与任务入口不假定相对先后。不改旧 r1～r14 绑定文件；README 仅追加。

模型：.build/fenestra-z62-model-r13-03/runtime/qemu-system-arm.exe；绑定 model-build.json、源码依赖及 EXE；不是旧 r69 来源恢复。默认 gate/sequencer/transfer-reset 完成逻辑仍开启，其他成功假设仍在。

范围：无参数、无卡、无控制器、无 Fenestra 候选；-nic none；127.0.0.1 RSP/QMP。仅只读、有界内存、硬件执行断点、原指令单 CPU 隔离单步。禁止客体寄存器/RAM/指令补写、调用/事件注入、伪造返回或 ready。原 PUSH/POP 等自然指令产生的效果单独核验。

预定上限：max_calls 默认16（8..128），准备最多 max_calls+64，事件最多8*(max_calls+64)，quiet15宿主秒，wall180（30..300），撤断点后运行到2主模型秒（1..6），不因失败放宽旧上限。全程跟踪窗口只到 trace_end；后续运行不监控全部任务。两独立 PID、两侧有效样本、无待配对才认定本局部样本通过。

通过内容：原句柄查表与同次TCB、原启动参数/帧、原 PUSH实际写栈、原返回 POP恢复及跳转、同TCB真实首次入口；仅自然成功 SVC 样本。所有异常、未匹配及上限失败保留。不证明完整失败/flags/System/删除复用/回调完成/并发/所有权 ABI，也不自动解释 r10 的73待配对。

阶段门槛不变：完整原Fenestra端口、真实业务与生命周期、空间/MMU/cache-DMA、模型可信度及同候选矩阵 Q1～Q6 全部通过，才冻结唯一镜像进入 U1～U6 认证/介质/擦写/NOR校准/持久化/中断恢复验证。前两阶段及独立物理恢复条件未满足，不上真机。有限模拟器结果不满足“真机一定不出问题”的绝对要求。无相机/USB/PTP/物理卡磁盘/刷机授权扩张。
