# r104：CW 四帧来源到受限预览

默认off属性`z62-capturework-preview`要求CW后端。r103及默认r75界面／r69内核保持。本模型采用实际CW输出、私有量化线性视图和既有C预览算子；不修改原厂指令、旧RAW计数或客体编码RAW，不发送事件6，不宣称物理ISP／AF等价。

## 来源与数据域

1. 只接受已完成全部有效行DMA的CW任务，限1514×1006／stride2272／RAW12／四槽配方。
2. 每帧用自己的冻结transfer解码，保存量化区间中点的私有linear12 packed视图及SHA。LUT丢失的低位不冒充恢复。
3. 同一配置代次、bank和epoch，四个不同slot／publication／真实地址都到齐后才交付cohort。重复一帧不能满足四槽；bank／配置／停止变化清除未完成集合。
4. 内部BQL接口只在完整集合有效时提供视图。消费者按值保存自己的四份输入；后续CW覆盖原物理ring或生产下一集合，不能改消费者已拥有的数据。
5. 未消费来源形成背压；新集合被丢弃而非排队积攒credit，stale通知不能重放。停止后要求四个新槽，reset清除来源及序列。
6. 预览仅按CPU提交的源地址读取私有视图，地址必须属于该cohort；输出仍通过既有全范围预检、实际NV12写回、IRQ和W1C。

源序列独立于旧`raw_stream_frames`。旧RAW／paired来源切换时释放CW私有所有权。当前CW来源不支持video配方、paired ingress或旧output-lineage标签，遇到相应上下文显式拒绝，避免把CW源标成旧RAW。

## 已验证范围

| 范围 | 结果 | 限制 |
|---|---|---|
| 新native | 16个已完成CW帧；3批／36路缩略NV12，共72,576字节独立核对 | 三种缩略几何，不称新来源的全部全分辨率配置已覆盖 |
| bank／域native | 14帧，错误bank拒绝、四个新槽后恢复、旧通知不重放；18,285,056字节客体编码RAW保持 | 没有改变物理相机或guest软件状态 |
| 私有来源 | 12帧共27,427,584字节的线性视图独立SHA核对 | 量化中点域，非原样本恢复 |
| 原厂24秒 | CW541、135集合、123份被接受来源、122预览批次；状态[] | 无GDB；有限统计取数有两次短QMP暂停 |
| 原厂LCD | 16个背景点均为RGB(210,60,17)，与最近实际输入的独立转换一致 | 固定色场、局部点验证，不能唯一确定显示的是四帧中的哪一帧 |

原厂旧RAW计数和metadata clock计数均保持0。没有靠新增事件6推进；首次观测到的预览由真实来源资格与原CPU提交共同产生。另一次生命周期实验中，蓝RGB(41,81,161)／橙RGB(210,60,17)各16个LCD点与来源匹配；但固定时刻的首次半按早于实际菜单进入，最后有效样本21.224059秒后出现通信超时，进程exit1。**两轮菜单及预览恢复未通过，超时根因未知**。动态非均匀场景、更多模式、完整摄影与刷机安全需独立验收，不能由这条像素通路替代。

新native前两次护栏检查失败来自测试把前缀放在内存池起点外：处理前已读回0。修正到有效池内后通过，两个失败及对应源已归档；设备模型没有为此改动。完整证据、限制和复现见[r104报告](../../docs/history/2026-11-04_实施-Z62采集四帧来源与原厂预览r104-report.md)。
