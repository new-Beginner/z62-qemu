# Z62 r7 原生 RAW 帧源合同

该层补齐已动态验证的RAW通道2完成链，仍不是ISP、统计处理或实时取景模型。属性 `nikon-z72-boot-config.z62-raw-stream` 默认关闭；启用时还需要已有 `functional-raw` 和帧同步时钟。r6原内核和主入口不覆盖。

## 数据和完成必须关联

原固件配置C26A0AC4的四槽描述符后，设备在帧同步的结束相位尝试实际RAW DMA。沿用r4的1514×1006、stride2272、实验packed12、受限RAM范围和全部描述符预检。每批实际写入四个槽，每槽2,285,632字节。

仅成功的本批事务会锁存 `20068290 bit8`，由原输入控制器产生IRQ96。固件实际路径为：

```text
IRQ96 / 1020A8FA
→ 1020A454，逻辑域200
→ 10239128，bank4 bit8变成任务事件4000
→ 10238B8A
→ 1023831E(200, C26A0AC4, C269FAE4)
→ 原固件重新提交描述符并切换bank
```

此前诊断使用的bank3 bit7（线路103）进入逻辑域10及1023C38A，受另一模式的flag4和mode1门槛约束，不是初始RAW通道2的完成。两条链的原始断点/参数证据在 `analysis/z62-liveview-r6/boundary-route/` 和 `channel2-route/`。

## 状态约束

- 只在Z62主engine启用；沿用现有z62-card-detect机型标记和master-role判定。
- 观察到20068008提交掩码200后武装；20068010对应使能位置位且20068018对应停止位清零时才运行。
- 20068014清除相应使能或20068018设置相应停止位时解除武装；必须重新提交后才能重启。
- 完成状态尚未消费时不覆盖下一批缓冲，增加blocked计数。这是有界背压模型，不是已恢复的硬件溢出行为。
- DMA校验失败不发通道2完成。读取诊断不产生数据或中断；重复高电平不是新帧。
- 仅本帧源发起的成功事务计入stream-frames。旧显式RAW提交仍透传给r5传感器完成桥，不冒充本帧源的完成。
- 系统reset清状态和计数；没有声称恢复所有独立寄存器复位命令或整机迁移行为。

帧时钟仍是现有实验时钟，时间间隔和像素打包不是硅片定论。每个stream-frames计数指一批四槽写入，不应解读成四张独立曝光或不同内容的视频帧；目前是静态合成图案。

## 只读诊断

`raw-stream-active`、`raw-stream-attempts`、`raw-stream-frames`、`raw-stream-failed`、`raw-stream-blocked`、`raw-stream-unrelated`。

目前原生单测通过全部四槽读回、真实IRQ96高/低、W1C、默认关闭、未武装、屏蔽、中途停止、失败不完成、背压、主从隔离、只读属性及系统复位。旧RAW/IRQ92回归在同一新EXE上通过。VMState增加到40，但未验收整机迁移。

## 当前原固件运行范围

不进MENU且不由宿主注入RAW/边界事件时，原固件驱动该源完成245批RAW事务，随后通过停止寄存器关闭它。已证明固件处理通道完成并重提描述符，尚未证明ISP消费了这些像素或LCD显示了成像结果。

不启用已有停止应答时，后续600、2、20、10命令各等待约3个客体秒。启用命令匹配应答后，可继续到mode1、flag4和新的通道1统计描述符，但仍是黑屏。统计缓冲内容、其自然完成来源和后续ISP是下一阶段。
