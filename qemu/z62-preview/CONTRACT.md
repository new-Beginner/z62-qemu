# r9功能近似预览合同

这是独立、默认关闭的实验设备。目标是让实际RAW数据经过可检查的转换和DMA进入原厂提交的三路图像输出；**尚未复现尼康完整ISP、统计处理、画质校准或任意处理节点**。不能用于验证真实曝光、色彩、降噪、锐化或修改滤波系数后的数值效果。

## 原固件证据

- r8无宿主像素/完成注入时，原厂自然提交11节点和18节点两组图：`analysis/z62-finite-r8/backend-payloads/trace.json`。
- `analysis/z62-isp-r9/native-contract/report.json`在22.100客体秒记录原厂寄存器、两张命令地址表、回调和中断转换表。所有新增观测窗口读取成功。
- RAW输入：1514×1006，stride2272，`20380310..31C`四个源地址；`20380048=05EA03EE`。packed12和RGGB相位仍是r7/r9的实验约定。
- 18节点图包含裁边后的1510×1002输入及三路输出。输出3为1920×1080、stride1920；输出4为1024×682、stride1024；输出5为1024×680、stride1024。
- 地址表使用`20102200`的四行，每行16字。当前`20102300`表为空；不能直接按命令bank编号推测另一张地址表。
- LCD最后使用`20144200=00300004`（现有LCD模型的NV12模式），Y=`EBC03800`，UV=`EBD30C00`，正好对应命令表某个输出4的Y和UV偏移。
- IRQ102由`103BF564`处理，前三条读取后实际在`103BF570/572/574`写回状态，属于W1C。`C1801E38`实际表将`20100020 bit2→逻辑1`、`bit3→逻辑80`，再由`103B754C`分别进入命令bank0/1。
- IRQ99由`1036BAEC`读取并写回`20380024`。启动时回调为`102E6F5E`，起流后实际变为`102E719A`，后者将选中原因继续转为`42190805`。错误掩码为`27EF2080`，普通输入/输出完成使用`1002`。

部分早期Ghidra导出把“读状态后原值写回”优化成普通RAM的冗余操作，故不能只依据它判断中断确认。当前导出器已将上述已知MMIO窗口设为volatile分析元数据，`analysis/z62-ghidra/isp-volatile-isr/`保留W1C写回，与Capstone指令核对。固件原件未修改。

## 已实现的功能近似

输入只能来自r7继承的RAW源刚刚完成的四槽DMA。设备记录其地址与批次，然后核对RAW处理器要求的四个地址确实属于这些已写入槽，不能仅靠配置寄存器或一个任意完成电平启动像素工作。

像素路径定义为：packed12解包 → 四边各裁2像素 → 每个RGGB单元组成RGB（两绿色点均值）→ 固定黑电平64和sRGB响应 → 最近邻缩放 → BT.601有限范围NV12。输出与LCD现有NV12解码匹配。这条路径是公开定义的近似，**不执行任意加载包中的矩阵、LUT、降噪、锐化、权重及其它裁剪算子**；相关参数目前仅保留配置读回。

只处理所观察的预览命令bank1配置、当前RAW布局和格式`09000201`的三个输出。12个输出全批预检后才写任何目标。Y/UV偏移及步长均来自原厂描述符，不写固定LCD地址，也不合成OSD。

本模型**不报告统计命令bank0完成**。11节点统计图及其输入/输出算法仍未执行，不能把显示图像或bank1完成解释为统计任务成功。后续应将近似运算逐步替换为有证据的节点实现。

## 边界、时序和生命周期

- 源地址必须来自本批成功RAW DMA，且完整RAW范围位于既有RAW池、实际可读RAM。
- 目标限定于既有Z62图像/帧缓冲池。全部Y/UV平面必须为可写RAM，禁止跨池、MMIO、ROM和软件状态区域。
- 允许不同帧对同一通道使用完全相同的目标范围（原厂实际存在这种复用）；拒绝跨通道或部分重叠。
- 支持偶数尺寸、最大1920×1080、stride不小于宽度且不超过2048，Y/UV行步长相同。格式和几何不支持时不完成。
- 一批实际读入4幅RAW并写出12幅NV12后，才置命令bank1状态bit3和RAW处理器状态`1002`。统计bank0的bit2不由此模型置位。
- IRQ102按各状态和对应mask相与，IRQ99按`20380020 & 20380024`。屏蔽保留状态，原厂W1C清除。未确认的输出会产生背压，不重复覆盖。
- 配置变化或显式停止取消尚未执行的定时任务。新的有效提交可以处理最新、尚未消费的RAW批次。
- `203800F0=FC400`及四个停止请求字形成完整排空请求，取消待处理预览后才报告`014A0000`。`1036C14E`的单实例20×14、stride32虚拟清空读会真实读取448字节，再报告输入消耗完成；它不写图像、不增加预览批次。
- 双实例清空、其它RAW尺寸和完整整机迁移尚未验收。1ms处理/排空延时是功能时序，未测量真机延迟。
- 自动路径只连接主引擎；从引擎和r8旧设备保持隔离。r9的新VMState版本不承诺兼容旧内核快照。

## 验证入口

```powershell
python -X utf8 -B tools/check_z62_preview_pixels.py --output analysis/z62-isp-r9/pixels-new
python -X utf8 -B tools/probe_z62_preview.py --output analysis/z62-isp-r9/qtest-new.json
python -X utf8 -B tools/probe_z62_preview_firmware.py --output analysis/z62-isp-r9/native-new --duration 22
```

所有输出目录/文件必须不存在。该Windows内核只有TCG，原生测试使用每个CPU地址空间中的合成ARM循环推进虚拟时间，未加载相机固件；不能把它与最后一条原固件实跑混为一谈。独立像素测试、设备DMA测试、原固件消费、LCD画面、长期运行、拍照保存分别验收。
