# Z6II 主副拨轮实验入口 r20

在 r19 的普通机身按键基础上，加入两只拨轮的正反向电气输入、相机内时钟队列和释放回零。沿用同一 r13 QEMU 内核，不是新的整机内核。**完整机身、快门／光圈调节、触屏、镜头及拍照保存仍未完成。**

## 启动与操作

双击 `start-z6ii-encoder-controls.cmd`，打开 <http://127.0.0.1:8677>。原有默认入口及 r19 入口都保留。

- “主拨轮／副拨轮”的“＋／− 一格”各产生一次完整两相序列；符号表示原厂计数正负，不是已测定的实体顺时针方向。
- 组合操作：保持键盘 **O**（ISO）按下，再点击拨轮；等待转动输入处理完再松开 O。曝光补偿键为 E，其组合效果尚未验收。
- “释放全部按键”释放机身按键并取消未执行的转动，拨轮沿不增加计数的路径回到静止；已经执行的步数不会撤销。
- 连续请求最多排队 128 个相位，超出会拒绝并提示，避免悄悄丢步。每个相位至少保持 20 毫秒相机内时间，实际等待取决于模拟速度。
- 网页“关闭模拟器”结束当前会话。候选包参数沿用 `--firmware`，限制见 [候选固件说明](README-FIRMWARE-TEST.md)。

## 已验证到哪里

| 范围 | 结果 |
|---|---|
| 两组物理输入 | 原厂控制器分别输出 +1／−1，另一只拨轮保持0 |
| 队列输入 | 经实际控制台队列后，原厂仍分别收到四个预期计数，未多计或串扰 |
| ISO组合 | 原厂收到按住ISO时的主拨轮−1、副拨轮+1；随后AUTO消失并显示Lo0.3 |
| 主拨轮独立改变ISO显示数值 | 尚未单独验收；自动ISO开启时，两次松键截图仍显示51200 |
| 原版／候选入口 | HTTP四方向、无效参数拒绝、双段快门、正常退出通过；候选健康未知 |
| 浏览器 | 四个拨轮按钮实点，后端16相位完成并回零 |
| 快门、光圈、其他模式／组合键 | 尚未完整验收 |

机身无镜头，F-- 是当前原厂响应，不伪造镜头光圈。数值变化是固件对外部电平的响应，宿主没有改曝光参数或调用固件函数。

## 复核

```bat
python -X utf8 -B tools\verify_z62_encoders.py
python -X utf8 -B -m unittest discover -s tests -p test_z62_encoder_queue.py -v
```

`/rotate` 接收 JSON：`{"encoder":0,"steps":1}`。encoder为0主／1副；steps是−32到32的非零整数。`/status` 的 `encoder_input.issued_phases` 是宿主发出的相位数，**不是固件已接受的步数**；固件消费由独立追踪证据验证。
