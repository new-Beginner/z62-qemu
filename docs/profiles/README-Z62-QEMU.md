# Z6II QEMU 开发版：r13内核与r16无镜头、双段快门配置

**这是可运行原固件和候选固件的离线开发模拟器，完整相机功能仍未完成。** 当前版本能显示原厂拍摄OSD与合成RAW测试图样，并已验证使用真实半按输入往返菜单后预览持续更新。默认启用合成参数、RAW、有限统计、近似预览、完成桥和CAPCOM握手，不能凭运行成功判断真机刷写安全。

另有独立的 [r22软件成像实验入口](README-Z62-SOFTWARE-CAMERA.md)，可在同一QEMU会话中使用C级场景／虚拟镜头、软件JPEG、目录卡、回放和删除。默认入口不变；该软件窗口不代表下文的原厂拍照链路已贯通。完整覆盖见 [能力清单](../CAPABILITY-COVERAGE.md)。

[r24原生场景入口](README-Z62-NATIVE-SCENE.md)进一步连接场景→原生RAW DMA→近似ISP／原厂LCD，并让部分机身按键与C级JPEG／回放共用输入。运行`start-z6ii-native-scene.cmd`，端口8681；原厂JPEG编码、NEF、视频、AF和更新安全仍未完成。

[r25媒体入口](README-Z62-MEDIA.md)在冻结r24设备上加入C级真实NEF编码、JPEG＋NEF成组存卡和仅NEF回放，运行`start-z6ii-media.cmd`，端口8682。原版／候选加载分支实际流程、独立RAW解码和NEF网页操作已验证；仅使用1514×1006预览RAW、12位有效精度写入14位，不代表原厂NEF或完整相机通过。

[r26b软件录像入口](README-Z62-VIDEO.md)加入同源已消费帧的静音MP4、v3混合卡和浏览器视频回放，运行`start-z6ii-video.cmd`，端口8683。录像为C级H.264/yuv420p，原厂录像／音频／照片视频拨杆及编码期间交互仍未完成。

[r27异步录像入口](README-Z62-ASYNC-VIDEO.md)将软件编码／审计移入受控后台进程，停止后可继续取景及操作软件曝光、镜头，并提供实际进度、取消和退出确认。运行`start-z6ii-async-video.cmd`，端口8684。最终267帧网页录像已播放到结尾并逐帧重放来源；该入口继续使用冻结r24内核，原厂视频、音频、AF及完整相机仍未完成。

## 一个启动入口

双击或运行：

```bat
start-z6ii-qemu.cmd
```

打开 <http://127.0.0.1:8675>。默认使用工作区中已校验的原 Z6II C1.70，不自动按MENU，等待原固件进入拍摄主屏。验证中约17秒相机时间开启主屏，实际等待取决于电脑速度，可能需要数分钟。菜单切换通常需要约5秒相机时间，索引变化后还需等待绘图。网页“关闭模拟器”会关闭该会话。

按 **MENU / M** 打开菜单；使用方向键导航；按 **半按快门 / X** 返回拍摄。**全按快门 / S** 自动包含半按，松开时先释放全按再释放半按；如果另行按住半按，它会继续保持。失去窗口焦点或释放全部按键会取消队列并释放两段。输入同时驱动MCU PG1/PG13和主处理器独立采集接点。当前默认模拟未安装镜头（PG0高电平），不模拟镜头协议。

测试自己的 C1.70 布局修改包：

```bat
start-z6ii-qemu.cmd --firmware "Z6_2_0170 (1).bin"
```

把例子中的原包路径换成自己的包。也支持 `--members` 指定包含完整 master.bin/slave.bin/controller.bin 的目录。候选模式默认关闭自动MENU，需要手动按键；内部状态地址未经验证，界面明确显示健康状态未知。输入的范围、CRC和未执行的另外两个外设成员见 [候选固件说明](README-FIRMWARE-TEST.md)。

CMD 显式启用实验参数，新增group23为零体与ENDM结束标记，**不是真实NOR或标定数据**。像素模型见 [r9说明](README-Z62-PREVIEW.md)。需要回退到先前r9内核和半按入口时运行：

```bat
python -X utf8 -B tools\run_z62_shutter_preview.py --experimental-parameters --capcom-sync --functional-raw --raw-completion --capture-preset init-mode --no-auto-menu --port 8675
```

当前r16配置只接受 `--experimental-parameters`，拒绝 `--parameters`，避免混入或覆盖真实NOR。虚拟卡仍默认快照，说明沿用 [虚拟卡说明](README-Z62-DEVELOPMENT.md)。目前尚未实现原固件拍照生成文件及回放闭环；快照运行后原卡哈希不变只能证明宿主镜像未修改。

## 当前实现

- 独立原生Windows QEMU 10.2.4，保留旧内核及原固件。
- CAPCOM请求/应答GPIO模型：实际请求沿后应答，通过IRQ65交回原固件处理。默认属性关闭，CMD明确开启。
- 原固件与候选固件使用同一个新运行入口，分别记录哈希和输入身份。
- 原生RAW帧源，以及从成功DMA的RAW计算30×12 LE-u16区域均值的有限统计设备。每批61槽全部真实写入后，原固件自行切bank、读取数据并继续起流。
- 成功RAW经固定裁边、CFA单元颜色、sRGB、缩放和NV12转换写入原厂预览输出，再由原厂LCD显示；这是功能近似，不等价尼康画质。
- `/status` 包含 `capcom_sync_status`、`raw_stream_status`、`finite_stats_status`、`preview_status`、`input_adapter`、`lens_contact`、`capture_input` 和 `monitor_transport`。硬件版本为r13，宿主及输入适配器为r16；没有新r16内核。缺失计数显示未知，`capture_acceptance`明确照片和完整模拟未验收。
- 监视器已修复一次读取超时后持续失效的问题：迟到回复按请求ID匹配，不自动重发控制操作。该次超时操作的结果仍标为未知，恢复读取不需要重启客体。

二进制：`.build/z62-capture-contacts-2026.10.29-r13/runtime/qemu-system-arm.exe`。

SHA256：`81406798183345e1aa975aada2c05151aa61c4514cfcee926fc8375cdf95c1fc`。

源码依据和边界见 [有限统计合同](../../qemu/z62-finite-stats/CONTRACT.md)及 [CAPCOM合同](../../qemu/z62-capcom/CONTRACT.md)。统计值为静止RAW的区域均值近似，并未复刻尼康测光、颜色校准及抗闪烁硬件算法。

## 验证与剩余范围

当前无镜头配置下，原固件使用纯半按输入完成两轮菜单退出、重开和导航；每轮返回后分别停留5.525和5.510客体秒，预览从522到681批、1051到1210批，状态列表为空、全按位未出现。截图确认菜单选择移动和两轮取景恢复。早期 `first-menu.png` 仍是切换前画面，不作为菜单视觉证据。这些结论仅覆盖当前模型与测试窗口。

本轮297项全量测试重新通过。r9设备原生qtest另覆盖数值、DMA边界、IRQ/W1C、停止重启、屏蔽及复位。r16原版/候选Python入口与实际CMD入口均验证了全按、四个硬件边沿、释放和正常退出，候选健康仍为未知。复核无镜头、采集许可和两轮预览：`python -X utf8 -B tools/verify_z62_no_lens_evidence.py`。监视超时恢复证据：`python -X utf8 -B tools/verify_z62_monitor_evidence.py`。

主屏出现不等于原厂已允许拍照。在当前配置中，其就绪标志约30秒相机时间才完成。PG0修正后原厂不再因不存在的镜头持续重连，全按可自然进入采集状态3；60秒观察仍没有新的照片RAW描述符或传感器帧完成。拍照保存仍未通过，不能把状态3当作照片完成。

后续追踪已确认：操作队列60项满载，采集工作入队返回0而被拒收；59项是准备帧回调。该回调反复耗时约0.3秒，其中一处100毫秒事件等待已实测超时。尚未补齐其硬件响应，不以增大队列、修改固件或伪造完成来绕过。证据与复核见 [r16报告](../history/2026-10-29_实施-Z62无镜头配置与双段快门r16-report.md)。

任意ISP节点及真实像素算法、统计bank0、正常拍照/NEF/JPEG/视频编码、原固件文件保存与回放、真实NOR/标定、机械及镜头行为、完整固件更新流程、长期稳定性和整机迁移仍未完成或未验收。修改未实现模块的固件，可能无法在此观察出问题。原始扩展输入0的停流恢复也仍未解决，不能把新半按验收解释为所有停止协议已完整。

详细目标与进度见 工作计划（本地证据，未分发：`GOAL-Z62-QEMU.md`）。本项目不连接物理相机、不访问物理盘，不提供安全刷机结论。
