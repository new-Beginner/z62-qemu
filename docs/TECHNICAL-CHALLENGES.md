# 技术难点与继续实现的路径

## 1. 更新包不是完整相机硬件资料

当前材料是固定 C1.70 更新包及已恢复的部分软件行为。它不提供完整复位 ROM、每台机身的 NOR/标定或所有器件规格。原始模块执行、菜单显示、软件媒体生成和“完整冷启动/更新安全”需要分别证明。

主/从 E6 和控制器按独立地址空间研究，不能把同一进程内的 CPU 编号当完整芯片拓扑。CPU/部分寄存器模型和实验初始化仍有假设；原厂指令实际执行也不自动验证全部硬件建模。

## 2. 数据、完成通知和应用状态是三件事

需要闭合的是“有效配置→真实输入供给→实际数值处理→DMA 写回→硬件完成→原厂消费”，不能只让等待返回成功。

r45–r48 将命令组 0/1、命令完成 81、单元结果 82 及不同回调区分。r48 的初始 5 次等待成功来自真实 RGB→packed12 和原厂回调，而不是宿主写事件。原厂 skip、计数消费和未消费尾项也必须保留。

共享 IRQ 的 W1C、屏蔽期间待定、未确认结果的背压、取消/停止、复位和从引擎隔离，均属于数据合同。错误数据或未供给的 RAM 不能被当成有效帧。

## 3. 当前最具体的缺口：切换后的新配方

| 已观察字段 | 初始配方 | 新模式配方 |
|---|---:|---:|
| 命令组 0 第二字 `20102644` | 40 / `28` | 34 / `22` |
| 命令组 1 第一字 `20102600` | `305` | `300` |
| 命令组 1 第二字 `20102604` | 1002 / `3EA` | 846 / `34E` |
| 操作类型/通道 | `0204` | `1D09` |
| LCD 尺寸 | 1024×682 | 1024×576 |

当前 grid/preview 软件模型明确只接受旧值。r49 中来源通知停在 767、统计停在 412 组、预览停在 616 批；最终两命令组已被原厂停止。视频 OSD 可以显示，但没有相应的有效图像供给。就绪字为 3 也不能单独证明恢复完成。

**下一项实施前置工作**：捕获新模式的 RAW 几何、缓冲、五路统计和六槽来源、两命令组的全部端口/地址表，以及实际物理单元 RAM 参数。34/846 只是已观察命令值，尚不足以推导完整 RAW 高度、stride、格式和所有写入范围。

取得合同后，保留 r48，在独立新内核加入 C 级运算，先做全样本/边界/失败路径，再验证原厂消费和双向切换。直接放宽常量检查会遗漏布局和来源约束，不能算解决。

## 4. ISP 可以先用软件，但要约束其含义

当前 RAW/RGB/NV12 和网格数学是显式近似，可推进交互和固件流程；无需先等到尼康所有硅算子被精确还原。

但它不能证明原厂色彩、降噪、锐化、PDAF、测光或实机画质。普通图像/RAW 不能默认等于内部 AF 统计。新软件函数仍必须处理合法几何、地址、只读输入、padding、重叠、取消和实际写回。

## 5. 原厂媒体与软件媒体不能混淆

C 层 JPEG、NEF 和 MP4 已使场景→保存→回放成为可测试流程。原厂拍照却仍受采集工作、准备帧队列、编码和客体文件系统链路约束。

曾观察到原厂入队被拒、等待超时后继续、卡初始化但不产照片。不能靠加大队列、清限制位或复制一张固定照片绕过。需追踪原厂实际接受的采集工作、输入描述符、编码请求、输出和文件写入。

## 6. Z 卡口与镜头闭环

可通过机身/控制器固件逆向镜头发送、接收、重试及状态机，逐步恢复识别、光圈、对焦动作、忙/完成与位置反馈。QEMU 可先在固件可见通信控制器处实现一支虚拟镜头，后续再校准更细的电气时序。

Tornado NKN 主要给出 PC→相机维修软件的线索。目前复用资料确认 AF Shift 校准，普通 AF/镜头步进完整链尚未恢复；这不等于原软件一定没有。必须追到相机→镜头驱动，不能将 PTP/维修操作码当 Z 触点协议。

第三方厂商获许可、社区逆向资料和完整公开触点规范也要分开。当前不把等待公开规格当成软件模型推进的前提。

原厂 AF 目标尚在后续阶段：原算法多帧执行→命令/反馈→镜头动作改变下一帧观测→统一场景下比较指标。没有真实标定时只能报告模型内结果；当前没有设计、替写或优化 AF。

## 7. 调试器和证据本身也会错

历史上出现过错误 Thumb/ARM 入口、TBB/尾调用/PIC 导出问题、错误调用帧、同一内存对象复用、单条 STM 命中多个写观察点、超时后的 QMP 缓冲失效和窗口末尾未返回。它们都可能被误当成固件或硬件问题。

因此保留原字节锚点、同 CPU/线程/SP 配对、前后值、源码/二进制 SHA 和失败记录；读取超时后不自动重放控制操作。长观察、空错误列表、截图存在和单测通过都不能单独作为整机成功。

详细失败与纠正在 [开发过程](DEVELOPMENT.md) 和完整阶段报告中。
