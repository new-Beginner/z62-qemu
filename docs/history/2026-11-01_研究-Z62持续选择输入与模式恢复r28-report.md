## 输入数据合同与分析工具修正

原控制器既有指令将pin0整理为持续选择值；原厂`10436600`的`10436AEA/10436AEE`将报文`+57`写入输入对象`+26`。本轮恢复了它后续的数据路径：

| 位置 | 经原指令核对的作用 |
|---|---|
| `1038DC0C` | 缓存主输入0x34字节，并登记输入处理工作 |
| `1038D886` | 将当前`C1F7A746`与前次`C1F7A77A`交给16位值比较器，输出对象`C1F7A628` |
| `103C9276` | 当前值、前值与变化布尔值分别写在对象`+0/+2/+4` |
| `1038D960` | 无新输入时用前值重建，变化标志清为比较结果；不是宿主写标志 |
| `103C93B4` | 读取输入复合对象`+7C`的当前16位值 |
| `103C93BA`／`1035CA6E` | 读取`+80`的变化标志，后者是原厂跳板 |

最初三个merge函数的导出出现BADSPACEBASE／Possible PIC construction；它们越过原始尾跳接入了无关代码。原指令明确显示`1038D95C→1035D1E8`为尾跳，`1038DA90→103C9276`为值比较器尾跳。仅在Ghidra脚本增加输入复制veneer分析边界，并先声明／分析比较器；不改原固件字节。

原质量检查实际exit1，保留于`analysis/z62-ghidra/selector-merge-r28-1`。修正后四个函数的重新导出及检查exit0，issues为空，见新manifest（本地证据，未分发：`analysis/z62-ghidra/selector-merge-r28-bounded/manifest.json`）。新导出34行的主merge不再带入无关数学代码；program.txt（本地证据，未分发：`analysis/z62-ghidra/selector-merge-r28-bounded/program.txt`）明确输入是raw模块、无PE／ELF导入表。结构检查通过不等于全部语义已验证；`selector-dispatch-r28-1/1020df2a.c`的旧间接尾部告警仍保留，不当作完整策略规格。

新增[分支检索工具](../../tools/inspect_z62_call_refs.py)，从校验过SHA的原始master搜索限定4MiB内的Thumb BL／B.W，独立检查每个半字边界，保留“数据也可能解码为分支”的限制。新4项测试先失败后通过，覆盖原厂BL、尾跳、错误目标、截断窗口和非法范围。

在`10200000..10600000`范围，检索`1035CA6E`得到`102A5838`的原始`BL`候选，见结果（本地证据，未分发：`analysis/z62-selector-r28/change-getter-callers.json`）。附近指令合并多个变化标志，推断属于综合输入变化检查；没有动态命中该点或确认后续模式策略，不把它称为照片／视频切换完成点。
