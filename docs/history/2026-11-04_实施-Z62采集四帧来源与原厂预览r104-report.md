# Z6II r104：实际采集四帧来源到原厂预览

分析与发布日期：2026-11-04。实现层级为 A 原厂提交／消费／LCD、B 有限传输及生命周期、C 近似像素运算。

r104 已把真实完成的 CaptureWork（CW）图像交给受限预览，24 秒原厂窗口首次在此新来源上完成 122 批预览并显示橙色场景。另一窗口证实输入蓝／橙变化到达 LCD。菜单返回测试仍未通过：固定时刻半按早于真实菜单进入，最后有效样本约 21.22 秒后发生宿主通信超时。默认仍为 r75 交互入口／r69 内核；本次发布源码和文档，不把预览进展视为完整相机、AF 或刷机安全验收。

## 实现合同及开发原因

r103 已有实际 CW 图像和统计，原厂拍摄 OSD 恢复，却仍绿色背景、preview0。旧预览的来源资格来自旧 RAW stream 或 paired 路径；CW 完成 DMA 本身不赋予这些来源身份。直接增加旧 RAW 计数、复制一帧或补事件6都会混淆因果，因此 r104 新建独立来源接口。

1. 只有实际完成全部有效行 DMA 的任务进入收集，支持有限 `1514×1006 / stride2272 / RAW12 / 四槽` 配方。
2. 每帧保存自己的冻结 transfer、完整量化 linear12 packed 视图 SHA，以及 epoch／publication／frame／虚拟时间／bank／slot／地址。LUT 编码 RAW 与私有线性域分别保存；重建值是量化区间中点，未恢复丢失低位。
3. 同配置代次、bank 和 epoch 的四个不同 slot、publication、实际地址齐全才交付集合（cohort）。停止／bank／配置变化清除未完成集合，reset 清理序列。
4. 预览消费者按值持有四份输入。生产下一集合或物理 ring 覆盖不会改变已拥有数据；未消费时丢弃新集合，不排队累积 credit，stale 通知不能重放。
5. 只有 CPU 实际提交的匹配源地址可读取该私有视图，沿用既有 C 预览算子、完整范围预检、真实 NV12 DMA、IRQ 和 W1C。不写 guest 软件状态，不发事件6，不增加旧 RAW 计数。
6. 新 CW 来源当前显式拒绝 paired ingress、旧 output-lineage 标签及 video 配方，避免套用错误来源。旧路径原生回归单独验证。

代码入口为 `nikon-z62-cw-preview-api.h`、`nikon-z62-cw-cohort.h`、`nikon-z62-cw-preview.h`，位于 `qemu/z62-capturework/`；构建 adapter 为 `tools/z62_capturework_preview_device.py`。完整边界见[合同](../../qemu/z62-capturework/CW-PREVIEW-CONTRACT.md)。

## 失败、纠正与未通过项

| 记录 | 结果与处理 |

| `native-1`、`native-2` | 测试前缀护栏失败；加诊断后证实处理前 `D4E00000` 池起点之前已读回0，护栏落在未映射区。只把测试输出移到池内 `...0100`，设备模型未改；失败及对应源分别归档 |
| `lifecycle-1` | `completed_observation=false`、`TimeoutError: timed out`、exit1、cleanup_failure=null；最后有效21.224059秒、preview102、状态[]。不能将其当24秒完成或恢复通过 |

## 复现与本次发布核验

需要已有完整父构建、原生 Windows Python 及 MSYS2 UCRT64、合法原厂输入和专用普通文件卡。公开新克隆不附带 `.build` 或这些输入；本次没有在空机器重建整条链。所有 TEMP／TMP／缓存位于工作目录；本机 Q: 只是已核对的同目录 ASCII 别名。

```powershell
$env:TEMP=(Join-Path $PWD '.runtime/tmp')
$env:TMP=$env:TEMP
$env:PYTHONDONTWRITEBYTECODE='1'
python -X utf8 -B tools/build_z62_capturework_preview.py --jobs 4
python -X utf8 -B tools/probe_z62_capturework_preview.py --help
python -X utf8 -B tools/probe_z62_cw_preview_banks.py --help
python -X utf8 -B tools/probe_z62_capturework_preview_original.py --help
```

原生探针需要已确认布局的 `--state`，原厂探针需要 `--card`、`--group23`、`--fixture`（C参考group17）及不存在的 `--output`。实际完整命令保留在相应结果的 effective_commands 和原厂 `command.json`，不要用任意跨机型 RAM 或工厂标定冒充该合成基线。原厂复现示例，输入须先按已校验合同准备：

```powershell
python -X utf8 -B tools/probe_z62_capturework_preview_original.py --card .runtime/migrated/c-runtime/fixtures/card-r22-4096.raw --group23 .runtime/migrated/c-runtime/fixtures/group23.bin --fixture .runtime/fixtures/group17-reference-r95.bin --duration 24 --wall-limit 600 --output analysis/z62-capturework-preview-r104/my-original-window
```

本次发布前实际重新执行下列只读数据复核（程序只在新证据目录写结果；不启动 QEMU／连接相机）：

```powershell
python -X utf8 -B tools/verify_z62_capturework_preview_evidence.py --native analysis/z62-capturework-preview-r104/native-3/result.json --banks analysis/z62-capturework-preview-r104/banks-1/result.json --original analysis/z62-capturework-preview-r104/original-1/result.json --output analysis/z62-capturework-preview-r104/publication-verification-1/result.json
python -X utf8 -B tools/verify_z62_cw_preview_lifecycle.py --result analysis/z62-capturework-preview-r104/lifecycle-1/result.json --output analysis/z62-capturework-preview-r104/publication-lifecycle-verification-1/result.json
```

两个命令 exit0，分别确认有限数据通路和保留的失败分类，不能混称两次功能通过。r98历史715项及 RawPy／LibRaw 本轮未重跑。公开源码检查、基础 C case 的本轮实际计数另写入公开 `docs/VALIDATION.md`。

本次公开副本实际执行35模块／143项无固件测试、16个GCC16.2.0严格编译基础C case，零失败／错误／跳过；1,015个导出SHA、670份Python内存编译、本地Markdown链接及被排除产物／凭据形态检查通过，860个未转换文件与研究目录逐字节一致。输出为公开副本 `analysis/publication/source-check-r104-20261104-1.json` 及同名 `.log`。这些基础C case不等同新增CW桥的全部设备行为测试。最终文档回写后再复核静态哈希及链接，不重复记作运行143项。

发布时通用归档器在 `publication-verification-1/source-snapshot` 遇到 Q:／D: 指向同一文件的重复键而拒绝独占创建，部分新副本保留、未覆盖。随后只读核对46个当前绑定均已被先前45份唯一文件的冻结 `verification-1/source-archive.json` 覆盖，逐份SHA一致；新生命周期复核的20份来源另已完整归档。该归档失败不影响数据复核结果，也未当成新增功能测试通过。
