# Z62 新模式数据合同与变尺寸 grid：r50–r52

日期：2026-11-03。普通技术/逆向报告，`flavor=null`。本轮用户恢复完整目标，继续优先任务一；AF 算法未改。范围见 [r50 scope](../../analysis/z62-mode-pipeline-r50/scope.md) 和 [r52 scope](../../analysis/z62-grid-geometry-r52/scope.md)。

## 结论

已新增并构建独立 r52 QEMU，补上实际捕获的 60×34 grid 配方，保留 60×40 原路径。真实原厂窗口中，bank0 比旧 r48 多完成一组实际数值写回，切换后的目标等待开始成功；未写原厂 ready、软件计数、队列或返回值。原厂返回照片后的取景有改善，但严格恢复验收仍失败，视频背景仍未成为有效图像，因此默认相机入口保持原样，完整目标继续 active。

这次不能简单归因为“RAW 停了”或“将高度改成846”。实际 RAW 格式字段始终为1514×1006、row2272；RAW 计数继续增长，停止的是统计和 grid 来源。下游 paired 则请求1516×854、row2288，MAIN 从特殊端口转成普通 RAM，WORK 启用。主输入、下游逻辑视图、统计和最终输出必须分开。

r50 `pipeline-1` 完成55.081客体秒、8份三阶段快照、关键读取错误0、exit0/正常关闭。r51 `inputs-1` 扩展 RAW0/1/3、另一前端、paired 0x800及生产者计数：其父窗口55.025秒完整，但请求错误属性名 `raw-reason`，导致27份行均known=false、CLI exit1。**失败原样保留**；除这一个属性外的数值字段成功读出。实际属性为 `raw-last-reason`，r52观察器以显式字段别名读取真实值，并为该错误新增正/负回归。

r51数值字段可限定地证明：RAW帧达到1415，统计/来源停767，统计失败与背压都为0；不能因整体known=false把已知数值变成零，也不能将其写成完整诊断通过。RAW0/1/3在该窗口没有被配置。Ghidra源函数 `102090A0` 与 `1020C334/340/34C/358/366` 明确了配置和四个DMA通道的区别，未把PC维修程序地址当固件地址。

## 3. r52 实现

- [变尺寸数值函数](../../qemu/z62-mode-geometry/nikon-z62-mode-grid-pixels.h)：C级三平面LE-u16整数均值→packed12。按真实行数与行跨度预检，失败不写输出；34行只写34行，尾部保留；40行与旧函数逐字节一致。仍不是尼康11个算子。
- [设备扩展](../../tools/z62_grid_geometry_device.py)：独立 `z62-grid-geometry` 默认off，仅扩展已捕获的40/34行，其他完整端口和参数资格保持。
- 单独 `z62-grid-retained-input` 默认off：作为C级实验，新的显式命令可对此前真实供给且仍有界可读的RGB重运算；不是新采集，ACK不创建新作业。取消、复位、背压和请求身份独立处理；物理缓存寿命未验证。**r52两组实际窗口中该计数均为0，不能归因说“保留策略修好了模式”。**
- 新状态序列进入VMState，版本47/minimum47；不声称旧快照直接兼容或整机外部模型快照完成。
- 新EXE、源树和17层身份清单独立，r48源及旧内核、默认入口未改。
