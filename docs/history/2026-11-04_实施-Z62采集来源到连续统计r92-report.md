# Z62 r92：CaptureWork 来源交付到连续统计

2026-11-04。已在独立 QEMU 中接通实际 CW DMA → 冻结量化线性视图 → 五路连续统计。原始 C1.70 的 **8.005927333 客体秒窗口产生 13 帧统计、2 个六槽批次，原厂 CPU 确认 13 次统计槽及 2 次批完成**，旧 RAW 计数始终为0。预览仍为0、1024×682 LCD 全黑，原厂摄影、模式恢复与 AF 未验收。

本实现为 A 原厂受控入口执行＋B 有限传输／通知＋C 量化数值模型，不能称为原厂 ISP 或物理 PDAF。r92 仍本地，云端最新是 r91／`a9088bf571c4f66d8629b1f60cee128203166110`；默认仍为 r75 界面／r69 内核。

## 阻塞与配置核对

r91 的连续统计只接受 `raw_accepted` 和 `continuous_source`，CW 刻意关闭旧 RAW 生产路径，因此新 CW 帧不能被它消费。此外，r91 原厂实验命令漏了 `nikon-z72-boot-config.z62-card-detect=on`；实际代码中统计 enable／时钟及预览支持都依赖该项。r92 原厂 wrapper 显式补齐配置，并启用独立数据桥，没有直接修改冻结的 r90b 驱动。

`grid-reason=disabled` 不是一个直接的 supported 布尔属性；缺少有效尝试时也可能保留初始 reason。r92 补齐 card-detect 后该 reason 仍为 disabled，不能仅据此认定硬件功能未启用。后续还要核对来源通知、四槽资格和预览尝试。

worker 使用任务私有输入及冻结 transfer：先生成原有编码 RAW，再用 r88 C 解码取得量化 linear16 代表值，经同尺寸无 LUT 的 C 核心生成私有 linear12。LUT8 区间 `[i*256,i*256+255]` 的代表值为 `i*256+128`，linear12 值为 `i*16+8`，不恢复低8位。

只有客体编码 RAW 的全部有效行实际 DMA 完成后，私有视图才取得来源资格。单缓存保存 generation、epoch、publication、frame、时间、bank／slot／地址与 transfer；未消费时阻止覆盖。统计仍检查原有 enable、commit、geometry、描述符、RAM、重叠、六槽及 W1C；五路真实写回后才释放来源并发原有完成通知。停止／取消／代次变化、统计 enable 变化和复位使旧缓存失效。没有修改原厂 ready、队列、返回值或旧 RAW 计数。

实现与限制见 [来源合同](../../qemu/z62-capturework/STATISTICS-CONTRACT.md)。`statistics_slot` 是最后消费槽，pending=true 时不能与当前待消费身份混为一帧。启用 CW 时仍阻止完整快照／迁移。

## 原厂状态与仍未完成的部分

实际内核 pattern 采样为：0共414次、08000000h共23次、04300000h共17次、04B00000h共158次，另2次未解析。相对目标 AND mask `05B00000h`，04B仍缺01000000h；这是采样结果，没有断点跟踪 setter／返回，不能证明采样间从未完整满足。ready_join／input_inhibit仍为1，队列头60，预览0；最终 LCD 已直接查看及像素检查为全黑。

本轮没有单独做“只补 card-detect”的原厂对照，因此不能用这两个原厂窗口单独量化配置和来源桥各自的贡献。原生默认关闭对照及源码门控分别证明来源资格缺口；原厂结论严格限定为组合配置下的13帧统计与CPU确认。

下一步需要完整四槽／cohort 来源、每槽冻结 transfer 与所有权，把正确线性视图交给 readout／照片和视频 ISP，并核对其它就绪生产者及预览支持条件。不能把一个CW新帧伪装成四个新输入，不能补事件或增加旧RAW计数。完整run/stop、inflight竞态、全局快照、原厂编码存卡、所有模式往返、真实镜头／PDAF与AF仍未验收；不能认证真机刷写安全。

## 复现

先具备工作目录内工具链、父构建、合法原始输入与专用虚拟卡，输出用新目录：

```powershell
$env:TEMP='<WORKSPACE>/.runtime/tmp'
$env:TMP=$env:TEMP
python -X utf8 -B tools/build_z62_capturework_statistics.py --jobs 4
python -X utf8 -B tools/probe_z62_capturework_statistics.py --state analysis/z62-capturework-contract-r86/state-1/result.json --output analysis/my-r92-native/result.json
python -X utf8 -B tools/probe_z62_capturework_statistics_original.py --card .runtime/migrated/c-runtime/fixtures/card-r22-4096.raw --group23 .runtime/migrated/c-runtime/fixtures/group23.bin --output analysis/my-r92-original --duration 8 --wall-limit 300
```

上述Q:必须已验证指向当前目录。完整回归的编译前缀配置为：

```powershell
$env:GCC_EXEC_PREFIX='<WORKSPACE>/.runtime/tools/msys64/ucrt64/lib/gcc/'
$env:LIBRARY_PATH='<WORKSPACE>/.runtime/tools/msys64/ucrt64/lib;<WORKSPACE>/.runtime/tools/msys64/ucrt64/lib/gcc/x86_64-w64-mingw32/16.2.0'
$env:LANG='C'
$env:LC_ALL='C'
python -X utf8 -B tools/check_z62_regression.py --output analysis/my-r92-regression.json
```

全部新源码、编译、TEMP、输入、日志与归档位于工作目录；没有访问相机、USB/WPD、物理盘或刷写。继承已有 Z62／Z72／WonderLantern／nightglasses 研究与署名，数值原语和有限设备路径为本项目显式模型，不把 NKN 的 PC 维修资料当作镜头协议或 AF 源码。本轮未修改 AF，完整 Goal 保持active。
