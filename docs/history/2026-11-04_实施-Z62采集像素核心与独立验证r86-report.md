## 开发与验证过程

先定位 Z72 CaptureWork 原型，再对 Z62 的实际前端、packing、LUT、缓冲、group 和真实事件 CB 做短暂只读快照。状态 probe 完成并 detach OK；无控制、无软件照片、无完成注入。实际读取不能替代原厂写入时序或已提交配置证明。

测试先因核心头文件缺失而编译失败，随后实现 standalone core。最终 DC5340 的 8 项 native C 通过；DC39944 完成 native-observed-2 全样本数值试验，DC40892 归档两 case 共 8 份源码，DC28288 的独立 NumPy 复核 exit0／1.20 秒。较早 native-observed-1 保留为历史，之后测试 fixture 扩充，不能拿它宣称当前源码哈希复验通过。

恢复后的再次 native 检查首次在编译阶段失败并出现 stderr 解码错误；未改绑定源码，在 ASCII 工作位置及 C locale 下实际 8 项通过（0.938 测试秒），另一次仅编译检查通过。未据此宣称已经确认唯一环境根因。公开检查器使用显式工具链、保存编译错误信息，不依赖私有 relocation manifest。

会话归档 115 文件后，只对自有 `http://127.0.0.1:8688` 发送 `/stop`，HTTP ok；DC34460 正常 exit0，最终 session clean_exit=true。未操作用户旧 8682 页，也未重跑已经完成的 r68 场景／r83–r85 内核观察。

## 尚未解决的合同

| 难点 | 当前证据与选择 |
|---|---|
| MAIN 输入 | 旧源为后级／辅助 RAW，不能冒充 `2020×1342` MAIN；先建独立虚拟生产者 |
| commit 与 bank/ring | 两套地址当前相同，不能判定 bank 含义；`BFI #1,#2` 不足以否定旧 bit0 语义 |
| transfer 域 | LUT 输出为编码域；旧 ISP 假定线性 Packed12，必须有不可变描述和明确逆变换 |
| 组曲线／系数 | 65 点曲线和 24 系数本次读回零，但写入／提交来源未知；不推论擦除，不代填成功 |
| 完成与取消 | 只有实际有效 run、合法来源、处理、写回和 ownership 后才发对应 IRQ；不能按核心返回成功批量满足其它单元 |
| 原厂功能 | 满队列拒绝及 AND 就绪不足尚未修复；原厂编码存卡、完整模式往返、AF、快照和长稳仍未验收 |
