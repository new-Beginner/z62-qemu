# Nikon Z6II QEMU v0.2.0 构建与验收报告

> 日期：2026-10-25；类型：本机固件启动实验环境（flavor=null）。

## 1. 交付结论

**已实际编译并交付 Windows 原生 QEMU 10.2.4 + `nikon-z6ii` 板型，不只是启动脚本或构建计划。当前是早期启动/调试版，不是完整相机模拟器。**

31 项测试全部通过，无跳过；真实主/从原固件均执行到第一次未知硬件访问，与独立 Unicorn 启动探针的位置和值一致。GDB 已验证读取原始 ROM、从 `0x10020000` 单步至 `0x1002BC88`；QMP 已验证暂停状态和单引擎双核查询。两个独立进程不等于双 EXPEED 通信已实现。

范围与授权见 [scope.md](../../analysis/qemu-v0.2.0/scope.md)。未连接相机、未修改输入固件，未安装 Linux，未向外上传固件。

优先双击项目根目录的 [start-qemu-v0.2.0.cmd](../../start-qemu-v0.2.0.cmd)。它启动主、从两个独立实例，遇未知硬件时退出并保留日志。退出码 2 在当前版本是明确的未建模边界，不是相机系统启动成功。

便携包：z6ii-qemu-v0.2.0-windows-x64.zip（本地证据，未分发：`dist/z6ii-qemu-v0.2.0-windows-x64.zip`），5,112,181 字节（约 4.9 MiB）；包内含程序、7 个运行 DLL、启动器、许可证和源码快照，不含尼康固件。解压后可把已提取的固件目录拖到包内 `run.cmd` 上。启动器需要本机 Python 3.12+，程序运行无需 MSYS2/WSL/Docker。

## 3. 构建来源与关键实现

- 原始源码：`https://download.qemu.org/qemu-10.2.4.tar.xz`，SHA-256 `821b545b92f165e57dddccac5077d76d4d436a226595b8813ad59306bbfd0746`。
- 架构参考：WonderLantern/z6-qemu 提交 `419a1f2a91a1f2d3a0209027c29606475f7fe26f`；该仓库没有 Windows 发布包，本轮未改动其工作树。
- 工具链：隔离 MSYS2 UCRT64，GCC 16.2.0、Ninja 1.13.2、GLib 2.90.1、Pixman 0.46.4、zlib 1.3.2，补充 dtc/libfdt。软件包安装保留官方签名验证。
- 新增 [nikon-z6ii.c](../../qemu/nikon-z6ii.c)：角色及固件指纹校验、ROM/SRAM/初始化数据存储、暂定 ARM/GIC 接口、严格未知事务处理、结构化现场记录。CPU、CBAR、GIC、定时频率是执行假设。
- 新增 [build_qemu.py](../../tools/build_qemu.py)：固定摘要获取上游、受限解包、机器注册、原生编译、递归收集非系统 DLL、生成版本清单和 ZIP。
- 新增 [run_qemu.py](../../tools/run_qemu.py)：运行前核对二进制/DLL/固件摘要、本机调试接口、主从独立实例、超时清理和报告。

未继承 Z6 C3.80 专用固件补丁或“未知读取返回成功”的行为，也没有修改 QEMU 的 ARM 执行核心。当前 ROM 64 MiB 是映射范围，不是已识别的 Flash 容量。

本轮修复了以下可复现宿主/框架问题：
1. MSYS2 首启 GPG 迁移/agent 挂起：使用归档内官方公钥、禁自动启动 agent，任务专用包配置仍要求包签名。
2. Python 与 shell 的中文路径编码：构建子进程统一 UTF-8。
3. MinGW `windres` 管道和绝对中文图标路径失败：使用 `--use-temp-file` 及相对源码搜索目录。
4. QEMU 10.2 自定义 ARM 机器缺少目标接口，被机器列表过滤：声明 `arm_machine_interfaces`。
5. RAM/ROM 所有者不能是普通 Machine 对象：使用 QEMU 允许的空所有者。
6. Windows ANSI 命令行损坏中文绝对固件路径：启动时选择固件目录为工作目录，传入固定 ASCII 文件名；原目录不搬动。

P1（path_type=callflow）：用户原始包已提取 payload → SHA-256 核对 → 原生 `nikon-z6ii` 载入 ROM → QEMU TCG 从 `0x10020000` 执行 → 原始分支 `0x1002BC88` → 在 `0x1002BDA4` 写 `0x04264000`、值 `0x21` → 记录寄存器并以代码 2 结束。没有写回输入文件或伪造外设完成事件。

验收还包括：原始固件哈希不变、上游参考仓库工作树未变、便携包 ZIP 完整性/摘要检查、包内无固件、根目录与包内两种批处理启动入口。临时映射盘符已经移除。

## 5. 尚缺功能

- `0x04264000` 起的启动外设模型：当前严格策略在第一处未知事务停止，尚未进入 RTOS 主流程。
- 进一步的 RAM/BSS、时钟、控制 MCU、DMA、图形/LCD 等硬件模型。
- master/slave 的远端窗口、通知中断和真实 DUALEG 通信连接；`--engine both` 仅运行独立实例。
- 原生 MENU、按键交互和图像处理。

因此，本轮完成了**可编译、可运行、可调试、可打包的 QEMU Z6II 开发底座**；完整相机行为模拟仍未完成，不能把 31 项测试通过解释成 MENU 或双 EXPEED 协作已经正确模拟。
