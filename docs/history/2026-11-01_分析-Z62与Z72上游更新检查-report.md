## 双 EXPEED 的可复用范围

Z72 的 `nikon-z72-dual-lab` 为 master、slave 建立独立地址空间，每侧两个执行核；消息 RAM 在两侧通过别名共享。两份固件代码基址相同，因此不能把 master、slave 直接放在同一普通地址空间。这一架构已是 Z62 R3 的重要基础；本地 r24 也沿用该基础逐层叠加，而不是把单芯片多核当作双 EXPEED。

源码已能证明机型布局不同：Z72 scatter 窗口为 `0xB1800000`，Z62 profile 对应窗口为 `0xC1800000`。GPIO、采集几何、描述符、参数区、原厂函数地址及 IRQ 仍需按 Z62 C1.70 逐项核实。上游新模型和旧 VMState／固定源哈希也不能直接混用。

## 上游尚未证明的功能

最新 README 明确保留“颜色、标定、完整捕获处理和照片文件未完成”。最新 `research/z7ii/capture_release_submit.md` 的 4 GiB 机身快门对照仍未命中所观察拍摄 API，没有照片编码、照片文件或写卡完成证据。诊断调用者能接受原厂拍摄请求，与物理机身快门正常产出照片应分别报告。

`card_file_service.md` 的 SDHC 对照确实观察到原厂新建 DCIM、NIKON 目录和 512 字节 `NIKON001.DSC` 记录；该文件不是照片。菜单门控更新中的卡、文件系统与闪存写入仍属主机替代，不能当作完整原厂刷写及断电恢复实现。

本轮没有重新构建或运行新 Z72 提交；上述功能结论是对代码、测试和其研究记录的核查，未冒称在当前 Z62 中动态验收通过。
