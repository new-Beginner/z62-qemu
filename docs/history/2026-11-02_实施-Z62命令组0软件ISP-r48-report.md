# Z62 命令组 0 软件 ISP r48 阶段报告

日期：2026-11-02；`flavor=null`。范围见 [scope](../../analysis/z62-grid-r48/scope.md)。

## 结论

独立 r48 已将实际连续统计 RGB 数据转换为四份 packed12 输出，写回完成后沿 IRQ102 交付结果和命令完成。原始 C1.70 自行处理 skip、增加命令计数及发布事件，5 次配对的 `81000000` 等待全部成功返回。输入和输出两次完整快照共 19,200 个样本经独立解码核对一致。

这是固定配置下的 C 级软件 ISP，传输/IRQ 为 B 层、原厂代码为 A 层。并未逐一还原全部 11 个尼康算子，没有验收模式恢复、原厂照片存卡、完整镜头/AF 或整机。默认入口不升级，完整目标继续 active。

## 实现

`bank0` 是编号 0 的命令组，`bank1` 是另一命令组，不对应两颗 E6 的编号。当前原厂提交分别有 11 节点统计图和 18 节点预览图；r48 对已观察统计配置提供一个软件复合处理实现。

输入为六槽中已供给的 RGB 平面，三路 LE-u16、60×40、row128；当前四个输入槽为 5/0/1/2。三通道整数均值后打包 packed12，每个输出 row96×40、3,840 字节，行尾 6 字节清零。四输出为 `8AF14400/8AF21C00/8AF2F400/8AF3CC00`，输入只读。该数学只是 C 级近似，不能用于宣称尼康画质、PDAF 统计或实机 AF 性能。

输入设备仅在连续统计五路 DMA 全部成功后发内部槽通知；它是来源追踪，不能解释成实机 GPIO。四个配置输入均供给且至少一个输入更新后，完成配置、RAM、数值、目标范围和重叠预检，再实际写回，最后锁存结果 `2010001C/10` 和命令 `20100020/4`。软件回调、事件和 bookkeeping 字段不参与成功判断。

新增状态和 timer 已登记 VMState46，增加加载合法性检查；整机快照恢复未验收。新开关 `z62-grid-process` 默认关闭，源和 EXE 独立冻结。

## Path 与原厂实际记录

P1，`path_type=callflow`：模型 RAW DMA→连续统计五路实际写回→内部槽通知→软件均值与 packed12 DMA→结果/命令锁存→原厂 IRQ102 派发→`42193081`→`10263D08`→原厂 skip 分支→`10263D34` 发布 `01000000`→目标等待自然返回。宿主没有写软件成功、计数、队列、取消位或调用原厂函数。

实际运行 12.048 客体秒、350 停顿，观察宿主时间 228.765 秒，正常 detach 和关闭 PID38108。34 组/136 输出/522,240 字节、拒绝 0，来源通知 196，预览结果批次 50。原厂 CPU 读到的 IRQ `(1C,20)` 分别有 `(10,4)` 1 次、`(71,C)` 33 次、仅预览 `(61,8)` 17 次，另有零状态 6 次；数值均为十六进制。

第一个命令回调的 skip=1，随后原厂自行减为 0；32 对发布点全部满足同线程、调用入口 SP=发布点 SP+16，命令计数各增 1。原厂同时消费这些计数，最后入口采样为 12，不能把 32 次发布描述成最终累计计数。5 次目标等待输出分别为 `63400000/63C00000/23C00000/23400000/23400000`，均含 `01000000` 且返回 1。时间采样落在同一毫秒，不能据此声明实际处理延迟为 0。

两次四输出快照保存全部输入和输出字节，独立逐像素解码共 19,200 个样本一致，padding 全零。窗口末尾第 34 个完成尚未进入源回调，保留未消费尾项。通用 `trace_complete=false` 保持原样，本次 `completed_observation=true` 只表示达到有界观察条件，不能等同原厂拍摄、模式恢复或无限期稳定成功。

## 验证、失败和复现

## 镜头协议问题及剩余工作

固件逆向可作为 Z 卡口通信恢复的主要路线。已有主/控制器固件镜头检测、启动、停止和重试链可复用；当前只建模无镜头接点及 C 级手动镜头，未实现完整镜头通信对端。应从固件驱动继续恢复设备身份、命令格式、对焦/光圈动作、忙/完成反馈和时序，先覆盖一支虚拟镜头；不把 ACK 当作动作完成，后续观测须受镜头位置影响。

Tornado NKN 恢复包是 PC 端反编译材料，不是完整原始工程或镜头固件。其 指令汇总（本地证据，未分发：`<PROJECTS>/tornado-nkn/recovered/z6ii-analysis/2026-10-31_逆向-Nikon-Z6II-指令汇总-report.md:1213`） 目前只确认 AF Shift 校准线索，普通 AF/镜头步进完整链未恢复；不等于原软件一定没有。PC→相机维修通信必须继续追到机身内部驱动，才能判断是否对应 Z 触点通信。

下一阶段先验收新内核的模式切换恢复及后续原厂数据消费者，再推进原厂拍摄、存卡与回放；另行恢复镜头命令与反馈。全控件、音频、原厂视频、整机快照与长稳、原厂 AF 多帧闭环及真实更新/NOR 仍缺。QEMU 通过不能证明实机固件更新安全。
