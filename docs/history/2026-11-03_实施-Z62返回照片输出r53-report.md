# Z62 返回照片的输出配方与重入：r53

日期：2026-11-03，普通固件／设备开发报告，`flavor=null`。授权及范围见 [scope](../../analysis/z62-photo-results-r53/scope.md)。只进行本地离线仿真，没有接入相机、刷写或发布。

## 结论

已构建独立 r53 QEMU，补上实际捕获的返回照片输出配方，并验证 active680 行的真实像素写回。原厂 C1.70 完成55.012客体秒观察、194次停顿并正常关闭；返回照片后 LCD 开启，原厂照片 OSD 和近似取景出现，预览持续增长且输出配置拒绝为0。后段统计来源与 grid 仍静止，十次新照片操作的目标等待超时，r49严格恢复判据仍为false。默认交互入口没有升级，完整相机、视频和 AF 没有因此验收。

本阶段代码不修改原厂 ARM、ready、队列、软件计数、等待返回值或超时。B级完成路由依赖实际C级像素工作；新的保留输入策略仍是显式实验，不能当作真实 ASIC 缓存寿命或一次新采集。

## 1. 根因与实现

r52的 `retained-on-1/pipeline.json` 在44.810／45.816秒记录：unit49返回照片时 active1024×680、参数窗口698行。旧 matcher 只允许该单元 active1024×682／700行，因而拒绝真实返回配方；不是简单的LCD开关问题。

| 改动 | 具体行为 | 层级与限制 |
|---|---|---|
| `z62-photo-result-layouts` | 新独立默认off选项，仅扩展上述unit49配方 | C级资格合同；不能放宽未知视频或其他单元 |
| 参数资格 | 在局部160字节副本中投影到旧资格函数，保留其余完整字段检查 | 不改客体参数RAM；opaque字段单独突变仍拒绝 |
| 像素输出 | renderer按实际active680行写Y／UV，完成四RAW与十二NV12后才发布结果与命令完成 | 不假写682或700行；不是原厂ISP数学等价 |
| 有限重入 | 与独立retained选项同时开启时，已完成34行后新显式40行请求可重算真实保留RGB一次 | 不是新采集；ACK／轮询不能自行重放，完成40行后不能无限重播 |
| 状态 | `grid_completed_rows`保存／复位／校验，只读`grid-last-rows` | VMState48、minimum48；未声称与旧快照或全部外部模型兼容 |

源码入口：[适配器](../../tools/z62_photo_results_device.py)、[纯C资格函数](../../qemu/z62-photo-results/nikon-z62-photo-results-profile.h)、[原生检查](../../tools/probe_z62_photo_results.py)。r48／r52及其绑定文件保留，没有覆盖它们的二进制后沿用旧身份。

## 4. 原厂55秒窗口

目录：return-1（本地证据，未分发：`<WORKSPACE>/analysis/z62-photo-results-r53/return-1/lifecycle.json`）。DC42640实际exit0，933.59宿主秒；客体55.012秒、194次停顿、10份三阶段配置快照、27份生产者样本均known=true且无读取错误。detach为OK，进程正常关闭。

外部pin0低／高为31.356／40.008客体秒。实体拨杆身份仍未独立确认。原厂bit2就绪回调命中3次；终态index3、LCD开启、ready3、input_inhibit0。

| 目标资源等待的实际调用范围 | 已配对结果 | 解释边界 |
|---|---|---|
| 低边沿前 | 5次，R0=1 | 原初始配方 |
| 低边沿后、高边沿前 | 5次，R0=0，约1.006–1.007秒 | 新模式等待仍有失败 |
| 高边沿后 | 64次R0=1、10次R0=0 | 64次成功属于仍在收尾的`1d09`操作，不能称64次新照片完成；后10次为`0203`照片操作超时 |
| 窗口末尾 | 1个未返回，0个无匹配返回 | 保留原始未完成状态，不补返回值 |

最后生产者样本在54.403秒：RAW accepted1424、RAW stream1415、统计／grid来源761、grid410、preview900、preview拒绝0、retained-jobs1。RAW accepted与stream是不同计数，不能混用。最后两个严格采样点52.676／54.237秒中preview851→896，grid保持410，因此r49要求两路均增长的恢复判据未过。

四张图已目视复核并记录SHA：before为照片取景，pin0-low为绿色背景上的视频OSD，pin0-high和final恢复照片OSD及近似取景。final仍有红色时钟图标。图像不能证明持续新场景，也不能把图标自行归因为某一种实机故障。

## 5. 下一步与未完成项

已新增独立r54场景响应观察器，在返回照片后发布亮、暗两份新C级输入，验证来源标签、实际RAW／NV12片段和原厂LCD像素；它不改r49验收门槛。实际结果另见其阶段产物，不能由五项专项测试推断原厂窗口已通过。

视频仍有上游1514×1006／row2272与paired逻辑1516×854／row2288的差异、普通RAM MAIN和启用WORK的独立生产／生命周期问题。不能把旧RAW按新stride直接解释，或只放宽576行／命令白名单。

原厂JPEG／NEF编码存卡、原厂录像、镜头协议及AF多帧闭环、完整控件／异常、全系统快照与长稳仍未完成。既有C级JPEG／NEF／静音视频另有自己的验证范围。模拟器不能保证修改后的固件刷入实体相机后不会变砖。
