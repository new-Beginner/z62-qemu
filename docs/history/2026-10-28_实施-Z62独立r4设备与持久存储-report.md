## 已实现

### 独立设备构建

新 runtime 位于 `.build/z62-functional-2026.10.28-r4/runtime/`，EXE SHA256：

```text
ad306ba7b0acc7a90837c6330da0379c02faf5405650d59a2a62ddc8cb3dfec6
```

固定 Z62 donor `4f4389944fc339d107f22f5f7ca3f90cc34b78de`，保留 r1 的 Z72 来源更新。参考 Z6 的四槽预检和有界 DMA 机制，没有搬用 Z6 几何/地址/辅助启动修改。

生成源码经过固定输入哈希与唯一锚点适配，独立编译/staging；构建 manifest 明确增加 functional_device，不能冒称纯 r1。旧 r1 EXE 的 SHA256 仍为 `e169431ed0a24dded62c2d3e0ea2aba1056385ec96584c57b40cd4e5ab29fba4`。

### 实验 RAW DMA

- 默认关闭，显式 `--functional-raw`；只由 `0x20068104=1` 提交驱动。
- 严格支持 1514×1006、stride 2272、配置 6、四槽非重叠处理池地址。
- 两组描述符选择，全四槽预检后写入；错选空 bank 不回退；engine-local address space 不跨主从写入。
- 合成 packed12，行末 padding；packing 和 bank 位含义仍是功能性实验假设。
- 成功后计数并发独立 raw-complete 脉冲；**未连接 sensor IRQ92**。拒绝事务不生成成功或完成脉冲。
- reset、只读 QOM、VMState subsection 已实现；整机 live migration 未验收。

设备细节及实际编译命令见 RAW 设备报告（本地证据，未分发：`analysis/z62-functional-device/REPORT.md`）。该报告覆盖不加载固件的设备测试；本报告补充下述原固件运行结果。

### 虚拟存储与宿主

- 空白 MBR/FAT32 创建，卷标、双 FAT、BPB/FSInfo 备份；独占创建，不覆盖已有文件。
- 默认 snapshot；显式 persistent 使用 ASCII 暂存副本，全部自有 QEMU 正常退出后才回写。
- 保存时源哈希冲突检测、大小检查、同目录临时副本校验、fsync、原子替换；异常保留恢复副本。
- 仅普通 `.raw/.img`，拒绝物理设备/符号链接。侧车锁仅为协作锁，不能阻止外部编辑器；不并行编辑源卡。
- r4 分阶段 QMP quit/等待/必要时终止；非正常退出不自动保存。
- `/status` 读取原固件完整错误列表和两 engine DMA 计数；未知不视作正常。网页明确标为固件 LCD、非真实取景。

### 未加断点的原固件循环

均使用原 C1.70、显式合成参数、无卡；不开主屏回放、不注入捕获边界、不写 guest 软件状态。探针 0.3.0 保持严格空状态列表规则，增加 r4/RAW 观测。

| 条件 | 结果 |
|---|---|
| r4 baseline / RAW off | 首次 MENU 可显示；4.325 客体秒已采到 `0x3F`；退出后不能重开；DMA 成功 0 |
| r4 init-mode / RAW on | 首轮退出/重开/导航健康，124,535 像素变化；第二轮导航虽也变化 124,535 像素，但列表 `[0x35,0x3F]`，严格失败后停止；未执行第三轮 |

RAW 组记录 **master 有效提交 3 次、拒绝 3 次、实际写入计数 27,427,584 字节**；slave 未执行 DMA。前期 3 次因配置不匹配拒绝，后期原固件提交满足合同并实际执行设备写入。此进展不只是测试描述符驱动，但尚未证明固件消费这些像素。

RAW 组最终 sensor init submissions=6、init completions=1、mode completions=2、mode2/frame completions=0。不能据此删除 one-shot，也不能把 RAW 写入成功等同于上层 event8 通知完成。

两组均已关闭。整体菜单循环通过值均为 false；**3 次冷启动×10 健康循环目标未达到**。证据：baseline（本地证据，未分发：`analysis/z62-development-r4/baseline-cycle/report.json`）、RAW/init（本地证据，未分发：`analysis/z62-development-r4/raw-init-three-cycles/report.json`）、复核汇总（本地证据，未分发：`analysis/z62-development-r4/verification.json`）。

### 动态定位第二轮 0x35

独立 r1/init-mode 断点实验锁定真实失败链：

```text
1039C318: wait(C18682AC, mask=8, limit=BB8)
27.144 → 30.160 客体秒
1039C31C: r0=0
1039C320: 调用 10397EC8，LR=1039C325，r0=2
103970D4: 追加 0x35
```

五候选返回次数 0/0/0/0/1；观察窗口内目标 `03030004` 通知 0 次。证实此上层等待超时路径，不证明底层 IRQ92/RAW/停流命令到通知生产者的因果。断点会扰动时间，不能与无断点循环直接当性能对照。完整证据见 上层等待报告（本地证据，未分发：`analysis/z62-upper-waits/report.zh-CN.md`）。

## 本轮未能打通的功能

1. **稳定重复 MENU/停流/重启。** 已缩小到真实等待链，缺事务至通知生产者证据；不能负责任地把猜测完成 IRQ 合并进基线。
2. **完整 RAW→ISP→LCD、持续取景。** 当前是有界合成输入，没有验收 ISP 消费、输出格式和持续 DMA 排空。
3. **正常拍照保存、NEF/JPEG/视频编码。** 存储扇区持久化是基础，不是摄影功能。
4. **真实 NOR/校准、设置持久化、AF/镜头/准确电气时序。** 合成参数不可当真实设备状态。
5. **完整快照/迁移与长稳。** VMState 子节已编码，未做 live migration/readonly overlay 专项测试。

这些是目前证据和实现的边界，不是声称永久无法实现；Z6/Z72 现有辅助/功能性模型也不能作为硬件准确性的证明。
