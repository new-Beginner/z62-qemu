# Z62双引擎统计诊断与停止来源：r60

日期：2026-11-03，`flavor=null`。范围见[scope](../../analysis/z62-statistics-observe-r60/scope.md)，执行顺序见timeline（本地证据，未分发：`analysis/z62-statistics-observe-r60/timeline.md`），命令与接口见[使用说明](../profiles/README-Z62-STATISTICS-OBSERVE.md)。只限本地开发、离线仿真，没有设备访问、刷写、AF修改或发布。

## 结论

已构建独立r60 QEMU，增加默认关闭的控制写入环与两个统计引擎的只读状态。新诊断native、连续统计和视频ISP回归通过，修正一个宿主录像进度文件共享竞争后，全量589项通过。r60q完成55.160观察器计数器秒的原厂照片→视频→照片窗口；视频新灰度和返回照片灰度均到达原厂LCD，严格模式恢复仍false。

已定位**当前模型的直接停机触发点**：sequence1109，原厂向`2006800C`写`0x10`，使`finite_started`从true变false。到最后控制样本没有新的`20068008`启动写入。早先“+14清使能误停止”的假说不解释这次停机，未据此修改硬件语义。真正的停止／重启合同及恢复路径仍需分析。

此阶段新增的是观察能力，不是新的原厂ISP、统计源、媒体编码或AF完成。r59b绑定源及EXE保留，原始ARM、ready、队列、等待返回值和超时未改。

## 4. 必须保留的证据边界

1. **采样尾段**：1907条master记录无序号缺口，覆盖已采区间0.008–53.757计数器秒；窗口结束55.160秒，末尾1.403秒未采环。旧`control_history_complete=true`仅表示已采记录连续。最新回执明确`full_window_control_history_verified=false`，不把最后未采部分补成“无写入”。
2. **两种时钟**：原观察器取04266008计数值／48MHz；ring直接取QEMU_CLOCK_VIRTUAL。固定counter与CPU generic timer共用整数纳秒周期：48MHz被截为20ns，产生约25/24比例并有初始化偏移。不能直接相减这两种秒值；本报告用明确时钟名、sequence及frame_count，不据此评价物理执行时间。
3. **PC精度**：11种候选PC中10种是实际STR；3条记录位于1020AB28的LDR，是写助手入口，实际STR在1020AB2A。所有基址寄存器值未逐条独立恢复，不能把候选PC都称为精确写指令位置。
4. **RAW不是物理旁证**：旧raw_stream_control在+08 bit200启动、+14／+18 bit200清锁存，忽略+0C；有限统计bridge则处理+0C bit10。此次同组+0C=200后RAW仍增长，是现有模型的不对称行为。真实控制语义仍未知，不能以RAW继续来证明相机硬件应忽略停止。
5. **寄存器覆盖**：r60q只观察QOM，不新增两CPU寄存器样本。首轮只有早期6份全寄存器数据，不能据此排除后段全部配置或其他输入路径。
