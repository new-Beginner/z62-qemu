## 对象首字解释的更正

`1035D43A` 的 R0 是指向封装对象的地址。封装读取 `[R0]`，再将值交给内核接口；R1 保持所需 mask，R2 被设置为 0，R3 接收原输出指针。将 `01000111h` 直接与 `05B00000h` 按位比较，没有内核对象合同的支持。它不能证明某个就绪位已经到达或缺失。

原始字节和双指令集复核（本地证据，未分发：`analysis/z62-prepare-control-r79/event-object-boundary-1.json`）同时使用 Thumb 解码封装、ARM 解码 BLX 目标，核对首字解引用和 SVC。早期仅用 Thumb 看 ARM stub 的探索输出未用于结论。未据此预设 RTOS 品牌或完整事件对象布局。

已更正 [r77/r78 报告](2026-11-03_研究-Z62采集拒绝与准备帧就绪等待r77-r78-report.md)和当前能力表。原始 JSON 中历史字段名 `input_event_word` 保留原字节及 SHA，只解释为“对象首字”，不反向重写证据。此前测到的入队返回 0、队列 60/60、等待超时及输出字 0 均仍有效。

只读检查还确认现有 C 连续统计成功写入五份有界 DMA 后驱动 finite-ready，连接至输入 101；旧 RAW 源完成四槽 DMA 后驱动的是 bank4 bit8（136），不能直接当作 bit7（135）的合同。它们是不同通知。当前没有证据允许把这些成功输出扩大成任意引擎的完成或永久 ready。
