# Z62 r101／r102：原始停止等待与数据驱动的内联读出

日期：2026-11-04。范围：离线固定C1.70、现有C级场景／参数，独立新QEMU及受控原始执行。未访问相机、USB/WPD或物理盘，未刷机、修改AF或写原厂软件ready／事件／返回值。完整Goal继续active；云端仍为已推送的r98／f9ed1dc，本轮新增内容在工作区。

## 本轮结果

r101直接捕获了前轮仅由返回组成推导的等待：原始kernel结果为0、FFCE0000h，外层布尔为1、0，第二次约100.701ms。消费者在mode2且mask已武装，但整个窗口的sensor实际数据源计数为0；第一轮成功所需800h已经在调用前存在，初始化完成计数为1。

r102实现并构建独立、默认关闭的C级内联读出。它确实消费显式2020×136 MAIN视图的所有有效像素，完整处理后才交付既有sensor completion输入，保留取消／复位和mode／mask／W1C合同。新native及旧CW／有限统计原生回归通过。

原厂16.001121500秒窗口中，新模型完成288次内联读出、有效158,238,720字节，319个接受源包均可逐字节重构，97份原厂实际消费者摘要独立重算一致。**但它在第二次等待失败之后才获得unit0启动资格，因此没有修复Error：3Fh和preview0保持。** 这一失败把下一步指向有限统计阶段的输入，不支持为使等待通过而取消unit0资格检查。

## r101：直接取证

新增`z62_stop_wait_observer.py`和`probe_z62_stop_wait_source.py`。使用原始执行断点Z1、撤除全部停点后的原指令单步，读真实事件CB；没有寄存器／软件RAM写入、inferior call或补完成。沿用已核对的ARM／Thumb宽度及固定C1.70 kernel布局，按CPU／SP配对。

13个停点中5个通用kernel返回属于其它SP／CPU，被明确排除；只配对两个目标等待。第二次sensor配置为10011h，mode8000h，maskF3h包含bit1，已是既有functional completion允许的mode2／mask条件。期间raw-source-events、raw-completions、frame-completions均0；init-completions为1。

原字节再次核对：1035D450h把底层非零结果映射为布尔0；102D7E26h的41081004h回调分支检查bit1，经102D7E52h向事件发布800h。本窗口在初始化之后附加，没有把“回调窗口未命中”说成整个启动从未执行回调。完整8秒观察正常收尾，detach OK，source／卡不变；独立verifier和14份源归档通过。

## r102：新的C数据工作

新属性`z62-input-readout`默认off。只接受已提交correction0、2020×136→2020×136、enable11h以及当前unit0控制资格；不把某个寄存器写入直接当成功。不支持其它尺寸／配置、完整CMOS／SDES／EX或真实器件时序。

`input-readout-file`复用既有Z62M／linear16软件视图ABI，严格校验普通有界ASCII文件、CRC、尺寸／stride、padding、epoch／publication、时间／帧号及读占用。按值拥有输入后，以明确的1ms C级传输延迟开始全行处理；逐个LE-u16样本求和、逐有效字节FNV1a64，保留源身份和行／字节统计。549,440有效字节处理完才脉冲数据完成输出。

输出接入既有functional sensor completion回调，继续执行mode、mask和W1C规则；没有写软件事件800h，也不增加`raw_accepted`。内联数据不经过客体RAW DMA，不能称为新的packed RAW采集。完整缓存、timer及代次处理在停止／reset／unrealize中取消或清理，CW的迁移阻止保持。详情见[输入读出合同](../../qemu/z62-capturework/INPUT-READOUT-CONTRACT.md)。

新增宿主包装器只根据实际QOM资格扩展既有虚拟时钟供帧，并把真实文件送到正确端口；它没有改宿主观察到的ready或设备状态。每个已接受packet的端口、epoch／publication／frame／time另有回执，原始header和payload均可重构。忙时不积攒帧credit，也不在几何切换时冒充另一个来源。
