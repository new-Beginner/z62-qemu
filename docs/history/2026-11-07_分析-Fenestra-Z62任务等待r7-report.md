## 4. 原厂静态合同与等待参数来源

### 4.1 保存点和恢复分支

这是原始 ARM/Thumb 成员，无常规 PE/ELF 导入表。E-imports 等价锚点为原厂 MPIDR/literal 当前槽读取、STR/LDR SP、条件 SVC、参数写入和原链表登记指令；合同包含完整输入身份和原始指令，不由其他机型布局推算。

| 项目 | master | slave |
|---|---|---|
| 保存SP后、切系统栈前的观察点 | `0x10107044` | `0x10038A18` |
| 调度循环 | `0x10107060` | `0x10038A34` |
| 当前项数组 | `0xC2B2A934` | `0xC189F6B0` |
| 位测试类入口 | `0x10111410` | `0x10042DE4` |
| 位测试类 SVC 后恢复位置 | `0x10111754` | `0x10043128` |
| 链首接收类入口 | `0x10112808` | `0x100441DC` |
| 链首接收类 SVC 后恢复位置 | `0x10112AAC` | `0x10044480` |
| 公共等待检查/登记入口 | `0x10120B48` / `0x10120AA0` | `0x10052540` / `0x10052498` |

上下文工具（本地证据，未分发：`<WORKSPACE>/fenestra/z62/task_context.py`）核对 TCB+0xBC 与现场SP、当前CPU槽与r8、原镜像角色、ARM SVC 状态；原LDR SP单步后仅 PC+4、SP切原系统栈，其余通用寄存器保持。CPU 编号不是 RTOS 任务ID，控制块地址数不是已确认任务总数。

普通恢复分支静态读取帧+0x40的CPSR候选和+0x48的PC候选；TCB+0x24=1走另一分支，不作普通帧解释。final_saved 只是对已观察地址再次读取有界原始字节，不能保证对象仍属于同一生命周期，也不要求其word18全部为ROM地址；少量不同值不能据此判定释放、任务死亡或内存损坏。

### 4.2 本轮新增的登记关系

等待关联工具（本地证据，未分发：`<WORKSPACE>/fenestra/z62/task_wait_provenance.py`）从各自原成员的唯一指令锚点恢复函数，核对原公共登记函数确实执行：对象+8 → 当前TCB+0x34，再进行原链表登记。条件 `SVC #8` 是调度切换点，不是硬件事件号。

- 位测试类：原代码按对象+0x14测试掩码，支持按位组合及原始选项；TCB+0x44/+0x48/+0x4C保存掩码/选项/输出指针，+0x40保存调用时SP。关联时要求这些字与保存帧中的原参数一致，且登记调用栈=保存帧地址+76。
- 链首接收类：原代码从对象+0x14取链首，空路径登记等待；TCB+0x44保存输出指针。入口先压入r0～r2再预留8字节，因此原句柄在调用栈+8，即保存帧+84；**不能把后来已被覆盖的r9当原句柄**。
- 例如主侧某次 `0xC2C15290` 保存点关联句柄 `0x01000003`、mask=2、options=1；这是该次登记字段，不能给它猜业务名称。主从相同数字也不等于同一对象。
- 关联只覆盖本次暂停原始关系，不读取未知对象链表，不证明该句柄当前仍阻塞、不证明业务任务身份/所有权、唤醒来源、超时正确性或同步安全。其余路径保持未解析。
- 内联12字节名称/28字节配置扫描仍未确认精确表边界，尾部候选混入相邻配置；没有套用其他机型任务数量或用地址顺序硬映射名称。
