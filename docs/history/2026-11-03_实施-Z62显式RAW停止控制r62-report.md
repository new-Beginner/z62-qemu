# Z62显式RAW停止控制：r62

日期：2026-11-03，`flavor=null`。范围见[scope](../../analysis/z62-raw-stop-control-r62/scope.md)，命令见[实验说明](../profiles/README-Z62-RAW-STOP-CONTROL.md)。仅本地离线仿真，没有连接设备、刷写、AF修改或发布。

## 结论

已构建独立r62 QEMU，默认关闭的新属性`z62-raw-stop-control`使RAW来源处理`2006800C bit200`停止请求。开启后实际原生验证显示帧数1→1、active=false、四个完整RAW槽不再被改写；新的+08启动恢复实际DMA。无关停止位、旧RAW回归以及停止选项ON下的统计／视频数值与生命周期检查均通过。

原厂窗口未完成：早期QMP暂时超时后曾继续推进，随后连续三次观察超时，在18.967观察器计数器秒结束，未进入模式切换。该失败不能证明本修改解决或破坏了完整模式恢复。严格恢复、原厂录像与整机均未验收，默认交互入口不升级。

## 1. 变更及构建

修改只在显式opt-in时，把+0C bit200加入旧RAW停止锁存条件；+14／+18停止、其他通道、数据算法和中断路由保持。没有增加完成／IRQ，没有强开统计或修改原厂ready、队列、等待及超时。来源仍是C级软件模型；有限控制路径有原厂指令依据，物理协议等价仍未知。

固定父源为r60；r60／r59b保持。独立目录`.build/z62-raw-stop-control-2026.11.03-r62`，VMState52/min52，22层身份链。DC10632构建exit0，428.08宿主秒。EXE SHA256：

```text
28b09a6294c09370d86f8c28f71599c53db11d52b94a3784360948321b1370d2
```

源码为`tools/z62_raw_stop_control_device.py`及独立builder／runner；实际生成修改只有`nikon-z72.c`配置bool／迁移字段和`nikon-z62-raw-stream.h`停止条件。构建绑定源不得改后继续沿用此EXE。VMState版本增加不等于整机恢复已经验证。
