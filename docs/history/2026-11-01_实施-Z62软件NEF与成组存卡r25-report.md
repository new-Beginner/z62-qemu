# Z62 软件 NEF 与成组媒体卡 r25 阶段报告

本阶段完成 C 级真实无损 NEF 编码、同源 RAW 校验、JPEG＋NEF 成组存卡、仅 NEF 回放与删除，并完成原版／候选加载分支的实际 QEMU 流程和 NEF 网页操作验收。默认原入口保留，新增 `start-z6ii-media.cmd` 使用 8682 端口；[操作说明](../profiles/README-Z62-MEDIA.md)给出格式、独立验证和来源许可。

这是 1514×1006 预览 RAW 上的显式软件编码。有效源精度仍为 12 位，左移两位写入 14 位；没有宣称原厂全分辨率照片、原厂 JPEG／NEF、ISP 数学、AF、视频或固件更新安全已经完成。原厂执行及设备仍沿用冻结 r24，QEMU SHA256 为 `dbe36d222dbfa633086f906f626968635c61d9825eaee8174480bef22a39abf2`。

## 实现与证据

| 实现 | 证据与结论 | 边界 |
|---|---|---|
| `tools/z62_nef_codec.py` | 真正的 F0 lossless14 差分／Huffman 载荷、TIFF／Nikon type2 元数据、JPEG 预览；RawPy／LibRaw独立解码 | 不是原厂codec等价；C身份明确 |
| 已消费帧到RAW | 校验RGB像素、帧号、虚拟时间及重构packed12 SHA；黑白测试得到256／16380，失配源拒绝保存 | 12位有效精度，几何来自预览合同 |
| `tools/z62_media_card.py` | 一快门一照片组；双成员容量；发布提交失败无可见半组；第二成员移动失败／删除清单提交失败均回滚，重开保持原文件 | 新v2目录卡，不自动升级v1；不是原厂SD文件系统 |
| `tools/z62_media_scene.py` | 默认JPEG＋NEF，可切JPEG／仅NEF；仅NEF实际提取内嵌预览；共用冻结r24边沿和已消费源帧 | 原厂曝光／镜头／SD播放器互通仍缺 |
| 原包实际运行 | [live-media-flow-2](../../analysis/z62-raw-r25/live-media-flow-2/media-check.json)：共享快门、JPEG独立解码及源重放、4倍回放、成组删除、仅NEF拍摄回放删除，关闭后重开空卡 | 不以HTTP排队成功代替保存 |
| 候选加载分支 | [candidate-media-flow-1](../../analysis/z62-raw-r25/candidate-media-flow-1/media-check.json)：同一流程与空卡重开通过，主进程exit0 | 本次使用原包走候选分支，健康unknown；不外推任意修改固件 |
| 网页实点 | ui-qa.json（本地证据，未分发：`analysis/z62-raw-r25/ui-qa.json`）：镜头0.65、仅NEF选择、拍摄／下载、实际回放4倍、删除及关闭；下载SHA与已提交文件一致 | 浏览器覆盖仅NEF；双文件组另有实际HTTP验收 |

原版与候选分支各产生两份 NEF，每份 1,523,084 个 RAW 样本与已消费源逐个一致，内嵌 JPEG 与独立解码器提取结果逐字节一致。另以黑、白、极值预测差分、全部14位值及固定种子随机数据进行五组内存中独立解码，每组16,640个样本全部相同。该压力验证测试编码域，不表示相机源增加到14位精度。

## 失败记录与修复

- 最初 codec-first（本地证据，未分发：`analysis/z62-raw-r25/codec-first/independent.json`） 与 codec-exif-preview（本地证据，未分发：`analysis/z62-raw-r25/codec-exif-preview/independent.json`） 的 RAW 样本已匹配，但 LibRaw 为 JFIF 首段的缩略图补 Exif，导致预览字节检查失败。把实际 APP1 Exif 移到 SOI 之后，不改变 JPEG 熵数据，保留严格预览相等检查；codec-validated（本地证据，未分发：`analysis/z62-raw-r25/codec-validated/independent.json`）通过。
- [live-media-flow-1](../../analysis/z62-raw-r25/live-media-flow-1/media-check.json) 因探测器漏建 `events` 列表中断。补齐该调用合同后，以全新目录重测实际流程，没有覆盖旧失败记录。
- 新媒体配置拍摄按钮从“拍摄 JPEG”改为“拍摄照片”，最终网页运行中的三个媒体核心文件与当前源码逐字节一致。
- 本轮首次全量391项运行有一项夹具创建失败：`test_signature_is_only_a_hint_not_a_valid_encoded_photo` 在 `create_fat32(...,512)` 的truncate收到 `Errno28`。失败发生于setUp，尚未执行照片断言。保留失败摘要（本地证据，未分发：`analysis/z62-raw-r25/regression-c-drive.json`），未删除已有数据或改动测试要求。
- 将本次测试子进程的临时目录指向 `D:/Z62-QEMU-runtime/sessions`，4项卡检查重新通过（76.842秒），最终全量 **391项通过，282.656秒，零failure/error**，见结果摘要（本地证据，未分发：`analysis/z62-raw-r25/regression-d-drive.json`）。摘要为工具输出的人工转录，未冒充已保存完整日志。

视频与音频、原厂全分辨率采集／编码／存卡、剩余机身控件、真实镜头协议、整机恢复和任务二原厂AF仍未完成。可参考的新Z72实现及其局限另见[上游检查报告](2026-11-01_分析-Z62与Z72上游更新检查-report.md)，不直接覆盖冻结内核。
