# Z62 r94/r95：参数来源更正与显式虚拟输入

2026-11-04。已把Z62采集组的参数读取链追到资源39，并以唯一诊断标签验证“虚拟group17→原厂资源缓存→参数缓冲→实际寄存器”。随后在独立、明确标注为C参考的输入下，冻结r93内核完成13次group数值／DMA，原厂CPU确认13次事件96。保留4组原厂DMA共256字节，其中216个已分类字节独立核对一致；710项完整宿主回归通过。LCD仍全黑、预览0，未完成原厂摄影／模式恢复／AF，也不认证刷机安全。

本轮不构建新QEMU：r94是被动观察，r95是独立参数输入及验证宿主版本，实际内核仍为r93／`bad3bc345bb152ddb3587beefbbf0a7dbd9a1ae30dc2f67ae872435752294dac`。默认r75／r69和原C1.70字节保持。范围见 [scope](../../analysis/z62-group-parameter-input-r95/scope.md)，使用与参数合同见 [GROUP-PARAMETERS](../../qemu/z62-capturework/GROUP-PARAMETERS.md)。r92–r95仍本地，云端最新r91／a9088bf。

## 参数字段更正与来源

上一轮把C26A0884h结构+58h误标为packed系数起点。继续核对底层wrapper后确认：+3Eh（C26A08C2h）由1020C132h→10208CB0h送入三行系数寄存器；+58h（C26A08DCh）走1020C13Eh→10208CF4h，是另一组配置。曲线指针槽仍为+80h（C26A0904h），1020C14Ah→10208DB6h读取65个u16。旧源码／回执保持，新的resource-contract明确撤回旧标签；r93数值模型使用实际寄存器，不依赖这一旧字段名。

Z62原表118D74C0h为`{0,11500h,2C00h,00270300h}`，资源ID39。实际provider链为1021F3E2h→103DFC14h→102ABBC0h→102AB28Ah，而非直接套用Z72的102AA02Ah。上下文+18h给资源地址；+1800h为主体，四套24字系数来自186Ch／18CCh／192Ch／198Ch，另套26B0h，曲线来自1A1Ch。原字节断言、literal及偏移推导在resource-contract-1中保存。

运行时被动读取确认C21835D4h上下文经C1861EF0h发布，资源来源C8159500h，曲线指针C25DAF18h。原provider记录中曲线位于+B4h，packed系数由24个u32的低字节形成。原始C1.70完整成员SHA仍为 `bb83613121f843d65101da936d942acdc513d86dbd3abc26259d0d870d03f5d4`；平坦ARM模块无PE/ELF IAT，原调用／literal／数据流为本轮E-imports等价锚点。使用既有Capstone工具，未宣称IDA服务或完整CFG已运行。

## 不能混用的来源证据

从C8159500h减11500h得到的128KiB候选缓存C8148000h，与staged group17只有10字节不同，但**并不逐字节相同**。差异包括B4E4h／B4E8h、末尾8字节；其余已设置的A124h／A420h特征相同。这不足以宣称整块镜像或解释所有缓存语义，失败比较保持为false。

为避免依赖全零相等，独立marker文件只把曲线第17点变为0123h，源文件其它字节保持。四次一致读取都看到该标签从文件进入资源RAM、实际65点曲线和寄存器；系数仍零，group继续拒绝／完成0。由此在本实验中确立了资源加载路径。原有合成基线的资源39体本来就是零填充；这不说明真实相机NOR擦除、固件损坏或已恢复实际标定。

NKN材料按既有边界复用：本地ROM配置README没有Z6II已绑定的初始化profile，EX读口报告也没有完整主ROM或真实参数dump。本轮未把PC地址、合成配置或EX窗口当作这套曲线的相机来源，未进行设备操作。

## 显式虚拟输入和实际工作

新生成器只接受冻结合成基线SHA `cf841bf675c03e6fd514121bcd130f05ae67039083ca7c3c5a203de052279ee4`，拒绝非零资源体、错误长度／尾标或覆盖已有输出。marker只改2字节；reference只改140字节，声明65点线性曲线与五套三组差分FIR。ENDM、其它资源和原固件成员不变。

## 失败记录与时序限制

origin-1在参数读取前发生QMP超时，无publication／无参数捕获，进程最终exit1；没有据此断言新暂停逻辑是根因或修复了旧QMP故障。image-1在早期硬件时钟频率尚为0时停止观察，进程exit0。新增clock guard只等待真实频率非零，不填默认频率、时间或成功值；四项专项覆盖早期零、坏字段、退出进程和超时。原生参数变换另有五项专项，均并入710项。

HMP一致读取会短暂停机，所有窗口均标注时序扰动与功能验收资格false。没有用宿主耗时评价E6处理时间或AF性能。reference-dma窗口内核pattern样本为0共566次、08000000h共15次、05300000h共15次，另2次未解析；没有实际跟踪AND等待返回。ready_join／input_inhibit最终仍为1，preview仍0、LCD1024×682全黑；不能把group／ACK计数当作整个就绪等待已通过。

下一步应跟踪原厂AND等待CALL／RETURN与实际帧对象的生产／消费，再定位四槽／readout／ISP来源交付缺口。完整相机、原厂摄影存卡、模式往返、快照、视频音频、镜头协议及原厂AF平台仍未完成。
