# Z62 r96–r98：连续供帧、真实等待与保留帧有限采样

日期：2026-11-04。范围：离线 QEMU、固定 C1.70、显式 C 级场景与参数；没有访问相机、USB/WPD 或物理盘，没有刷机或修改原厂 AF。本文采用普通固件研究报告结构，证据、结论及后续路径分别列出。

## 结果与边界

r96 直接观察到原厂 AND 等待在慢速输入下两次成功、一次超时；此前“所有其余就绪生产者均缺失”的判断过宽。r97 按实际客体时钟连续供 MAIN 后，三个已配对等待全部成功，原厂进入新的 61 槽有限统计阶段。r98 增加独立、默认关闭的保留帧来源，使这一阶段完成两批、122 次真实 DMA，旧 RAW 采集计数始终为 0。

**122 次有限采样使用同一份保留图像，不是 122 个新 RAW 帧。** 原生两批 93,696 字节逐字节独立重算通过；原厂两批各保存一份 768 字节统计，均与对应保留 RAW 的冻结量化线性域独立重算一致。16.000750250 客体秒的完整观察正常退出，但最终 LCD 显示 `Error. Turn camera off and then on again.`，预览计数为 0。没有完成原厂取景、摄影或完整模式恢复，不提升默认 r75 界面／r69 内核。

## r96：原厂等待的直接证据

新增 `z62_live_ready_observer.py` 和 `probe_z62_current_ready.py`。复用原厂会话的 GDB，使用真实 `Z1` 执行断点。单步前撤除相关断点，保留原指令执行；没有寄存器改写、软件 RAM 写入、inferior call 或补 IRQ。

| 对象／位置 | 固定 C1.70 锚点 |
|---|---|
| 原事件对象／真实 CB／pattern | C188808Ch／C2C39A08h／C2C39A1Ch |
| 外层 CALL／BOOL RETURN | 10238804h／10238808h |
| 原始 kernel result | 1035D450h；SP 为外层 SP−16 |
| ARM wait／AND BICS | 10111410h／10111628h |
| 实际 setter entry／store | 101110ECh／101111C4h；store 帧 SP−40 |
| 五类生产 mask | 00100000h、00200000h、01000000h、00800000h、04000000h |

慢速诊断供帧间隔为 500 ms，原厂等待约 200 ms。三次等待为 81,471,937 ns 成功、201,787,521 ns 超时、116,127,750 ns 成功；成功输出包含 05B00000h。45 个实际停点、detach OK，8 秒观察完整且进程 exit 0。该证据纠正了旧非原子 pattern 采样的解释，不代表旧 r69 模式失败已经修复；断点本身也扰动时序。

## r97：按虚拟时钟供 MAIN

`z62_main_stream.py` 用实际 64 位客体时钟计算 `frame_id = floor(time_ns × 30 / 10^9)`。硬件或缓存 busy 时不积累供帧 credit，不补发突发历史帧；publication 只在实际接受后推进。只有两个原子替换 mailbox，两种诊断 RGB payload 各保存一次，每次保存完整 96 字节 header 和 SHA，因此所有 accepted packet 均可重构。接受发布与实际 DMA 完成分别计数。

`probe_z62_main_stream.py` 的 r97c 窗口 `stream-3`：32 次 accepted、32 次 CW/group、31 帧连续统计。三个 AND 等待均为 kernel 0／BOOL 1，用时 25,937、9,438、28,042 ns。3 个 gap 只统计实际相邻 accepted frame ID；原厂停采后的尾部不算丢帧。另一无调试窗口为 33／33／32，不混用计数。

原厂随后停 CW，写入 `2006A548h=60`、目的 `89C48400h`、geometry `0C1Eh`，请求 61 槽、30×12 标量。旧 finite 模型已经启用，但只认 `raw_accepted/finite_source`；CW 保持旧 RAW 计数为 0，故理由为 `source`，不能靠增加旧计数绕过。

关闭后另存 `closed-console.txt`、`closed-command.json`，避免将仍在写入的日志尾部或已清理 runtime 元数据作为完整证据。MMIO 解析使用 CPU0 过滤，同名 `board_view=master` 不足以区分另一 CPU 的设备视图。

## r98：独立保留帧来源

新属性 `z62-capturework-finite` 默认关闭，依赖 CW 与 `functional-finite-stats`。只有 CW 全部有效行实际 DMA 成功，才保存冻结量化 linear12、transfer 与 epoch／publication／frame／time／来源代次。CW stop 或配置变化后保留，global reset／unrealize 清除。

finite_prepare 从保留私有图像计算既有 30×12、row64 的 u16 区域均值，每份 768 字节。一个 batch 的图像与来源冻结；之后完成的新 CW 只更新 latest cache，不能改变已运行 batch，下次请求选 latest。沿用实际槽资格、DMA、IRQ／W1C，没有写软件 ready、扩大队列或改变原厂返回／等待。源与输出 canonical RAM alias 拒绝。详情见 [有限来源合同](../../qemu/z62-capturework/FINITE-CONTRACT.md)。

原生测试 4 个进程全部 exit 0：两个实际 CW 输入，共 122 次有限采样 DMA。缺 source 不完成、取消的 CW 不保留、CW stop 保留、后续 acquisition 不改 owned batch、下次选 latest、reset、source/output alias 和默认关闭保留 legacy gate 均通过。旧有限统计原生回归也通过。

原厂首个 8 秒窗口为 33 次 CW／group、32 帧连续统计、两批有限采样成功，但仍黑屏。随后独立延长到 16 秒，保存每批首次成功 DMA 的标量、保留 RAW、冻结 LUT 和源身份；两批都对应 publication 33、frame 61、time 2,047,019,729 ns。最终出现原厂 Error，CW 未恢复、预览为 0。延长观察没有改动原厂 200 ms 等待。

## 失败与更正记录

- r97 stream-1 完整运行后暴露 Q:/D: alias 比较问题；修改前源已归档。旧 `console.txt` 最后一条未闭合，不作为完整轨迹。
- stream-2 误读取不存在的 QOM `finite-source`，启动后即停止、publication 0；失败和源保留。stream-3 只读取真实属性后完成。
- r98 native-red-1 在旧 r93 缺少新属性时失败，按红检查保留；不是 r98 正向通过记录。
- r96 第一次源归档因 runtime command 被清理而失败；后续只使用逐字节相同已保存副本，保护失败记录不覆盖。
- 原厂出现 Error 是明确的功能失败。进程 exit 0 表示观察器正常收尾，不能解释成相机功能通过。

## 复现

在已有合法 C1.70、r73 工具链锁和父构建的研究环境内，先设置 TEMP／TMP 到工作目录；新输出目录必须不存在。公开新克隆不附带这些私有输入和历史构建缓存。

```powershell
python -X utf8 -B tools/build_z62_capturework_finite.py --jobs 4
python -X utf8 -B tools/probe_z62_retained_finite_dma.py --card .runtime/migrated/c-runtime/fixtures/card-r22-4096.raw --group23 .runtime/migrated/c-runtime/fixtures/group23.bin --fixture .runtime/fixtures/group17-reference-r95.bin --output analysis/my-r98-original --duration 16 --wall-limit 480
python -X utf8 -B tools/verify_z62_retained_finite.py --native analysis/z62-capturework-finite-r98/native-1/result.json --original analysis/my-r98-original/result.json --state analysis/z62-capturework-contract-r86/state-1/result.json --output analysis/my-r98-verification/result.json
```

复核器包含当前两批／122 采样和实际几何的范围断言。不同窗口若产生不同合法结果，应另建版本并按证据解释，不能修改原厂窗口去迁就断言。构建有父依赖，见 [采集后端](../profiles/README-Z62-CAPTUREWORK-DEVICE.md) 和有限来源合同。
