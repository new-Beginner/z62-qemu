# Z62统计停止调用来源、有限父帧与RAW停止缺口：r61

日期：2026-11-03，`flavor=null`。授权范围见[scope](../../analysis/z62-statistics-control-r61/scope.md)，执行记录见timeline（本地证据，未分发：`analysis/z62-statistics-control-r61/timeline.md`）。仅本地离线仿真／分析，不接入设备、不刷写、不修改AF，不发布。

## 结论

在冻结r60内核上新增了原厂控制调用快照和有限父帧分析，完成55.034观察器计数器秒的照片→视频→照片窗口。60个调用现场、48次启动／停止写入与1953条已采控制环记录逐项复核，结束行也取得最终环；两引擎28份样本均已知、无序号缺口，原厂进程正常退出。594项全量回归通过。

切换时的统计停止来自原厂上层停止接口，固定帧布局支持以下有限路径：`1023002C → 1023881E → 1023C5A6 → 1020C820 → 1020AE72 → 1020A832`。实际逻辑停止掩码为`0x2EB`；统计逻辑位3映射到物理停止位`0x10`。不能通过删除+14停止条件或强开统计来修复这条路径。

另有实际原生失败：同组RAW停止请求`2006800C=0x200`未被当前RAW模型处理，来源继续产生下一代DMA。已据此建立默认关闭的r62独立实验层；其构建／原生／原厂结果需分别验收。r61没有修改r60的任何完成语义，严格模式恢复仍false。

## 1. 新增实现与边界

| 组件 | 实际行为 | 不支持的推论 |

两份专项分别3项和2项，均先红后绿。停止帧的错误保存LR会阻止继续展开，不能把栈中碰巧像代码的值当作完整调用栈。

## 2. 有限调用证据

| 阶段 | 现场 | 实际关联 |
|---|---|---|
| 初始统计启动 | 0.922／4.999／9.326计数器秒的AAFE store | LR指向C806的BL；静态路径为C802提交68100／68104的8，然后尾入AE3E并写68008=10 |
| 启动父帧 | 原始64字节栈中的+44保存LR | 为1023AAC5，对应1023AAC0的BL C7A8；该函数先配置统计，再调用启动接口 |
| 初始停止 | 4.984／9.235秒的A832 store，值10 | LR指向AE84的BL，使用AE7C带命令通知的停止助手；与切换停止包装不同 |
| 第一次切换停止 | trace sequence75，31.902计数器秒 | A832写0C=10；LR1023C615，原BL C610→C820；r5与保存的上层r4均747，即2EB |
| 第二次切换停止 | trace sequence102，40.330计数器秒 | 同一有限路径与逻辑掩码2EB；统计启动锁存此前已关闭 |
| 停止父帧一级 | 当前SP+12保存LR | 102388A3，对应1023889E的BL C5A6 |
| 停止父帧二级 | 当前SP+60保存LR | 10230031，对应1023002C的BL C3881E |

C5A6只分配16字节固定保存帧，C3881E分配48字节，C820／AE72／A830不改变SP；这些限制支持上述保存槽解释。它们不是通用unwinder，也不证明更高层所有任务／回调来源。

静态C5A6按逻辑位调用通道停止操作：位3调用C820，并最终写物理0C位10；2EB也包含RAW逻辑位9。原始mode切换现场因此有明确的多通道停止意图。统计停止不是宿主自行发出的请求。

## 3. 实际窗口与缺口

窗口55.034观察器计数器秒／976.69宿主秒，414停顿。新增结束采样已覆盖本次请求窗口结束行，控制环master1953／slave0，没有缺号；GDB观察到的48次68008／6800C写入与环的地址／值顺序完全一致。这里的“覆盖”不包括随后调试器清理过程，`debugger_cleanup_interval_observed=false`。

第一次切换停统计的环sequence1137位于QEMU虚拟时间30.627337453秒／frame918。原观察器秒来自04266008／48MHz，QEMU ring时间来自QEMU_CLOCK_VIRTUAL，沿用r60已记录的20ns整数周期／初始化偏移边界，不直接相减两类时钟。

最终控制样本中主引擎RAW accepted1443、统计767帧；slave仍均0。父周期末样本grid414组、preview1028批、video149批、video拒绝0；MAIN1,149,612,480字节／WORK766,408,320字节。统计停止后没有观察到新的统计启动store，严格r49恢复false。

本次有两次视频before读样：35.187秒像素数值匹配，但完整`pixel_response_verified=false`；36.250秒才满足完整before条件。新灰210在38.429秒匹配，返回照片灰40在49.114秒匹配。四份记录均重算RAW／十二NV12片段和LCD区域；不能把首次数值匹配写成完整阶段验收。有画面响应不等于停止／重启、原厂编码和保存通过。

## 4. RAW停止原生红阶段

`raw-stop-red.json`使用同一个r60 EXE，先实际完成一代RAW DMA，然后清状态、用A5填满四槽，再写`2006800C=0x200`并给下一边界。

实际结果为active仍true、RAW帧数1→2、四个RAW槽未保持A5，因此`stop_request_honored=false`，验收要求下exit1。这与冻结源码只处理+14／+18停止、未处理+0C一致，不能把RAW继续增长当作相机硬件本应继续的证据。

下一实验只增加显式`z62-raw-stop-control`：启用后+0C bit200清RAW启动锁存，停止后需原厂新的+08启动。默认关闭，既有r60保留；不发完成、不改统计启用、不改原厂状态。是否能解除原厂恢复问题尚待实验，不把此原生红阶段写成模式恢复修复。
