# Z62 多地址写观察修复与实际工作阶段来源 r43b

日期：2026-11-02。本轮修复了宿主调试器在一条原厂批量存储覆盖多个写观察点时反复停在同一指令的问题。相同固件、内核和QEMU参数的修订版完成18.007客体秒，读到142份实际阶段表及278条原生写观察。三个工作线程的前置poll已定位；工作首字被确认是构造时从操作对象首字复制的值，不能称为全局分配代数。原厂图像处理、模式恢复和整机目标仍未完成。

## 范围与实现级别

授权及离线范围见[scope](../../analysis/z62-selector-r43/scope.md)，flavor=null。原厂执行观察为A，本次功能修复位于宿主`trace_z62_upper_waits.py`及新阶段观察器；没有新增设备成功响应、改写guest字段、缩短原厂等待或更换默认入口。

样本为原始C1.70 master成员，包含CRC的SHA256为`bb83613121f843d65101da936d942acdc513d86dbd3abc26259d0d870d03f5d4`。它是原始ARM模块，无PE／ELF导入表；二进制和两个冻结EXE身份已重新核对。

## 批量写导致的调试器重入

首次origin-1在0.991客体秒出现反复停顿。原1035D2EC为`STMHS.W R0!, {R2,R3,R12,LR}`，一次覆盖从C2D1A9C0开始的16字节，包含C2D1A9C0和C2D1A9CC两个写观察地址。旧工具只撤下已命中的一个写点，执行单步时另一点再次触发；旧代码把任何T05回复当作单步完成，重新布置观察后又重复该指令。

这属于观察器缺陷，不能解释为原厂固件死循环。确认PID55484／stage5_m6c8jv后主动终止该负面实验；exec31079退出1、process_closed=true，ConnectionResetError来自主动停止。失败现场（本地证据，未分发：`analysis/z62-selector-r43/origin-1/intentional-abort.json`）、完整捕获输出与两份修订前源码均保留。

修订为每条被观察的原指令暂时撤下全部活动内存观察点；完成单步后恢复。原先多读点和单写点的支持保留。新增校验拒绝将含watch／rwatch／awatch的嵌套停顿当作指令已执行，避免读取并发布伪“写后”值。整个过程不写原厂寄存器、指令或RAM。

| 对照 | 原版负面实验 | 修订版origin-2 |
|---|---:|---:|
| 最后客体时间 | 0.991秒，主动中止 | 18.007秒，达到虚拟时限 |
| 总停顿 | 1049 | 582 |
| 1035D2EC停顿 | 1000，其中999次仅撤下一个写点，末次中断于操作中 | 88次，全部暂撤两个写点 |
| 结果 | 未完成，无完整成功回执 | exit0、detach=OK、process_closed=true |

两次归一化QEMU argv相同；原厂固件、设备内核和原时钟未变。次数不是性能基准，修订版运行范围更长。单条批量写可能覆盖多个被观察存储单元，当前按触发点保存写前后值，不声称逐一枚举了该指令所有写操作。对照见watch-step-comparison（本地证据，未分发：`analysis/z62-selector-r43/watch-step-comparison.json`）。

## 实际阶段表

新工具`trace_z62_work_stage_origin.py`版本`2026.11.02-work-stage-origin-r43b`在102675F2入口核对LR1029A77F、R4阶段对象的work指针、部件R6及当前poll，再读取20条12字节记录。142次入口全部匹配，三个表的完整SHA各自恒定；其余记录为空、setup均0、flag均0。

| 线程对象／阶段表 | 观察数 | 到达102675F2前的poll |
|---|---:|---|
| C18649E8／C2BB43D8 | 62 | 1026A300 |
| C1864B38／C2BB41A8 | 32 | 10269CF8、10269446 |
| C1864980／C2BB4090 | 48 | 1026B3D2、1026B5EA |

这些是运行时表的实际内容，不能用ROM中重复片段替代。前置函数指针已核实，具体函数内部各条件分支尚未逐个动态覆盖，表的存在和进入末段不等于全部数据处理成功。

两批Ghidra导出五个函数，原始字节均未改变。1026B5EA有类型传播未收敛告警；自动结构检查未列出问题不等于该告警消失。涉及返回类型、复杂参数结构和数学行为，仍以原Thumb和后续动态合同为准。

局部代码表明：1026A300包含C18647D8／80800000／参数1000等待，10269446包含81000000／1000等待；1026B3D2可构造请求并等待同对象的200条件。1026B5EA还包含请求构造、缓冲管理及条件回调。这些是软件同步与处理入口线索，尚未对应到可直接补发的硬件IRQ或已完成的像素运算。

142次末段入口中，work+4为0有122次，为1有20次。取消标志非零的记录仍能到达收尾包装，进一步说明102675F2被调用不能当作处理成功。

## 首字来源及同地址角色变化

对r42发现变化的C2D1A9C0和C2D1A9CC保存278条写观察，其中99条值变化。启动期和池管理期间该地址未必是work；字段名只是固定偏移标签，不能把所有数值解释为操作对象指针。

原103D3464构造路径和实际寄存器／写后值共同验证：

| 客体时间 | 原指令位置 | 已核对的实际写入 |
|---|---|---|
| 1.141秒 | 103D3584，`STR R5,[R7]` | R7等于观察地址，写入另一个work指针C2D1AD00；此时该单元作外层包首字段 |
| 1.546秒 | 103D359A／103D359E | R5等于观察地址，+C写入R4操作指针C2D06200；原359C先从操作首字加载R0，再写work首字4 |
| 1.951秒 | 同两处构造写点 | 操作指针变C2D07580，work首字变6，均与现场R4／R0一致 |
| 3.163秒 | 103D3584 | R7再次等于观察地址，写入另一个work指针C2D1EFC0；该存储单元再次作包首字段 |

原指令还显示两次构造请求分别以R0=2CC和3E44调用同一分配助手，并把返回对象存入R7／R5。这里只核对这些局部参数、寄存器和写入，不外推全部分配器生命周期。

因此，work首字在该构造点来自operation[0]，尚未确认它的完整业务单位或全局唯一性。同一个地址也确实被用于不同对象首字段，不能凭地址和mask把r42的早先取消与后续等待串成同一请求。局部原始字节和QEMU argv对照见work-field-contract（本地证据，未分发：`analysis/z62-selector-r43/work-field-contract.json`），全部动态样本见[summary](../../analysis/z62-selector-r43/summary.json)。
