## 新增能力

- `z62_action_queue_console.py`：读取 `C23D9F14` 的六字队列头，严格核对 RAM 范围、92 字节 stride、容量、计数及 head，按环顺序还原工作 ID。头读取前后比较，但明确 `atomic_snapshot_proven=false`，相同头也不能证明整个读取原子化。
- 同时读取 `C23E2948` 的 40 字采集上下文及 `C181D330` 的 APPLV 区域，保留原始 words。未初始化或畸形队列返回 unknown，不补空队列。
- `run_z62_action_queue_console.py`：独立组合 r74 永久故障保存和 r75 控件层，经 workspace 启动器运行；生产 QMP 默认 5 秒不变。
- `record_z62_action_evidence.py`：保存实际生成源 SHA、日志前缀和阶段摘要，拒绝将已发送快门的运行标成“快门前绑定”；显式允许缩小为后段绑定，字段会保留 false。
- `probe_z62_action_queue.py`：后续运行的独立包装，在首个诊断 HTTP 请求之前同步完成源绑定；保持原 probe 的输入、等待和失败标准。仅该包装的调用顺序专项已验证，本轮已完成窗口仍保持“后段绑定”的事实，不重标。
- `analyze_z62_capture_pending.py`：重新计算原 master 全哈希，使用实际 Capstone 对两个有界 Thumb 区间逐指令核对掩码测试，将旧反编译线索与当前采集样本交叉验证。

原厂回调 `103EC626` 在 `103EC654–103EC672` 调用 `103F4CE0`，参数为 `r3=60h`、`r2=7FFFFFFFh`；后者实际 Thumb 指令读取 `context+14h` 后执行 `BICS r0,r3; ANDS r0,r2`。因此测试的是 **不被 60h 豁免的 pending 位**，不是“等待 60h 到来”。该回调指针对应的采样出现 4080h 和 4000h，均不能被该掩码排除。这是原始指令和当前 RAM 的交叉证据；没有逐调用断点，不能将 RAM 中的 result word=4 写成某次特定调用的动态返回记录。

## 复现

从工作目录运行；绑定输出必须取新名字。当前默认 UI 入口仍是 r75，r76 只用于诊断。

```powershell
& '.build/tools/video-r26/Scripts/python.exe' -X utf8 -B tools/run_z62_workspace.py --entry run_z62_action_queue_console --port 8688 --software-card artifacts/my-r76-card --diagnostic-output analysis/my-r76-faults
```

将实际输出的 session 路径用于新包装 probe；它在原 probe 自行创建日志后、首个网络读取前完成绑定。本轮窗口在包装实现之前已结束，不声称本轮具有全窗口 r76 源绑定。

```powershell
$env:TEMP='<WORKSPACE>/.runtime/tmp'
$env:TMP=$env:TEMP
& 'Q:/.build/tools/video-r26/Scripts/python.exe' -X utf8 -B tools/probe_z62_action_queue.py --session '<WORKSPACE>/.runtime/tmp/z62-reference-lu7o2ake' --output analysis/my-new-r76-observation
& 'Q:/.build/tools/video-r26/Scripts/python.exe' -X utf8 -B tools/analyze_z62_capture_pending.py --master '<WORKSPACE>/.runtime/tmp/z62-reference-lu7o2ake/inputs/master.bin' --case analysis/z62-action-queue-r76/photo-then-mode-2 --output analysis/my-new-pending-check.json
& 'Q:/.build/tools/video-r26/Scripts/python.exe' -X utf8 -B -m unittest discover -s tests -p 'test_z62_action*.py' -v
```

第一条 probe 必须在新会话／空专用卡运行，不可在已有这次会话中重放；上面的真实 session 名用于说明参数结构。第二条可复核已保存记录；master 所在 session 若已清理，应改为同完整 SHA 的原始输入文件。
