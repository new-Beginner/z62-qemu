# Z72 新提交分析与 Z62 参考适配

日期：2026-10-27。适配版本：**2026.10.27-r1**。

**结论：已移植可复用的肩屏寄存器设备、输入追踪和采样实验开关，完成全新 Windows 原生编译、93 项回归及原固件 A/B 运行。Z72 的“两个采样开关消除退出错误”不能直接套用 Z62：本机两组退出后均出现致命 Error，且不能重开菜单。**

此版本不是完整相机模拟器，也不是原有 v0.4.0 严格探针的替换版。没有连接相机、刷机、修改客体指令或强写应用状态；没有启用主屏实验/捕获边界注入。仍使用显式合成参数，不是工厂 NOR/校准恢复。未制作或发布安装包，未提交或推送 Git。

## 3. 已落地的适配

### 独立、可复现，不改捐赠工作树

[适配器](../../tools/reference_updates.py) 在**新生成源码树**应用精确锚定改动，在**临时控制台副本**应用主机侧改动。肩屏和 I²C 文件取自固定上游提交并校验 SHA-256；控制台必须匹配本地构建清单、二进制及适配器哈希。

[构建入口](../../tools/build_reference_qemu.py) 增加显式 `--z62-updates`，旧默认行为不变。新版构建在 `.build/z62-reference-2026.10.27-r1/`，没有复用或覆盖已转换的旧生成树。

### 输入追踪

[追踪头文件](../../qemu/reference-updates/nikon-z62-input-trace.h) 保留上游记录地址/值/读写方向的设计，并修正：

- 上游不足 256 条时使用 `total % 256` 作为起点，会从尚未写入的槽开始；改成短环从 0 开始，满环才按模索引。
- 总计数用 64 位，复位时清零；QOM 计数及日志不可写。
- 新 VMState 为 38 且最低版本为 38，不承诺加载旧快照；本轮没有验证迁移/快照功能。

默认设备属性关闭；新版 CMD 显式开启追踪。没有修改采样读返回值、客体 PC、应用索引或采集状态列表。

### 肩屏与采样配置

- 用专用 panel 器件替换 Z62 台架已有的地址 0x0D 通用寄存器银行，保留原合成 initial-state；`/status` 输出寄存器图像、页及计数。
- 不搬 Z72 肩屏 RAM 快照地址。两机型控制器完整成员哈希不同：Z72 为 `cb10af00...a128a9a`，Z62 为 `9c65cad5...e416983`；不能当成同一固件布局。
- `--sampling-source` 只打开 Z62 已有的 `sensor-sample`、`sample-counter`，默认关闭。保持 Z62 自己的帧同步实现。
- Z72 **旧基线**还含“同步字为零时由模型自动写回 0xFFFF”的 0x20061000 重臂逻辑，Z62 不含该逻辑。它不是此次 8 个新增提交之一，本轮没有无依据搬入。因此 A/B 验证的是“两开关直接复用”，不是声称完整等价的 Z72 采集模型移植。
- 不移植更新安装 UI、Z72 启动断点/RAM 地址或肩屏探针中强行调用固件函数的实验步骤。

## 4. 验证结果

### 编译与设备

- 原生 Windows/UCRT64 全新编译，1315 个构建步骤完成，退出码 0；清洁 PATH 下版本、机器、属性及 SD 帮助检查通过。
- EXE 大小：10,150,981 字节。SHA-256：`e169431ed0a24dded62c2d3e0ea2aba1056385ec96584c57b40cd4e5ab29fba4`。
- 输入环测试通过：默认关闭、单条短环、读写顺序、范围过滤、256 条回绕、只读属性、复位、双引擎隔离；不加载原固件。
- 上游肩屏合成程序测试通过：身份、页回读、自动递增存储、计数及复位；控制器 GPIO 测试也通过。这是器件契约验证，不是原厂自然肩屏上电验收。
- 最终完整回归：**93 项通过，零跳过，58.450 秒**。新增 7 项主机测试覆盖源码范围、幂等拒绝、显式开关、只读诊断与 EXE/清单失配拒绝。
- 新 CMD 实际执行原包准备及 `--help` 通过；未授权单独启用采样/追踪开关会返回参数错误。

## 6. 使用与复现

默认配置启动：双击 [新版入口](../../start-z6ii-reference-2026.10.27-r1.cmd)，先关闭同端口旧实例。当前已另行重启一个默认实例于 `http://127.0.0.1:8662`，回到原始菜单；采样源关闭，输入追踪开启。退出后重开的故障仍存在，需用页面重启恢复菜单。

下面命令在项目根目录、Git Bash 中运行；`TOOLCHAIN` 是已安装 MSYS2/UCRT64 路径，`PI_SCRATCH_DIR` 为本机会话 ASCII 临时目录。

```bash
# 若本地尚无新提交对象，先 fetch；不会切换子模块工作树

git -C third_party/z72-qemu fetch origin main

# 构建目标必须是全新目录；已存在的成功/失败目录会拒绝重用
python -B tools/build_reference_qemu.py z62 --z62-updates --msys2-dir "$TOOLCHAIN" --work-dir .build/z62-reference-new-check --jobs 12

# 原固件菜单运行；二进制须匹配该适配器的构建清单
python -B tools/run_reference_console.py z62 --z62-updates --input-trace --experimental-parameters --qemu .build/z62-reference-2026.10.27-r1/runtime/qemu-system-arm.exe

# 在另一终端测试已启动实例；输出目录必须不存在
python -B tools/probe_reference_menu_cycle.py --url http://127.0.0.1:8662 --output "$PI_SCRATCH_DIR/menu-cycle-check"

# 采样源实验需要重启控制台，在运行命令后额外加 --sampling-source
# 菜单探针是观察程序；退出码 0 只表示流程执行完，并不代表重开成功。
# 必须检查 report.json 中 reopened_menu，以及退出截图。

Z6II_QEMU_REQUIRED=1 python -B -m unittest discover -s tests -v
```

肩屏契约测试可从固定上游源码重现：

```bash
mkdir "$PI_SCRATCH_DIR/z72-panel-check"
git -C third_party/z72-qemu archive 4a7bed36b6e747f58d5ab25f31b06a31fa7c6ec2 | tar -xf - -C "$PI_SCRATCH_DIR/z72-panel-check"
python -B "$PI_SCRATCH_DIR/z72-panel-check/tests/test_controller_panel.py" --qemu "$PWD/.build/z62-reference-2026.10.27-r1/runtime/qemu-system-arm.exe"
```

## 7. 剩余阻塞与边界

下一条有证据支撑的推进路线是：**恢复 Z62 采集重启检查的原固件调用链和外设完成条件**，而不是修改应用索引、抹掉 0x3F 或把模型状态字无条件写成成功。

本轮未恢复该硬件合同；未验收真实传感器像素、取景、拍照、录像、SD 卡完整栈、肩屏实际段码或设置持久化。原来的两个参考环境和严格探针都继续保留。
