## 1. 这张图实际表达什么

图的核心不是“整台相机已经可用”，而是**哪些事务有执行者、实际输出和完成通知，哪些连接还没验证**。

| 图示部分 | 可读出的含义 | 不能据图断言 |
|---|---|---|
| MAS、私有SLA、EX/SPI | 分离主从执行环境与控制器通信；部分只在bundle模式存在 | 真实硬件CPU/电气时序已准确复刻 |
| 描述符选定输入/输出RAM、有限图形执行 | 处理受支持的命令并产生实际输出，再给完成状态 | 完整LUT/ISP、任意命令都可执行 |
| CMOS timed DMA、actual DMA DONE、capture IRQ | 数据写入与事务完成必须有关联，不应凭空报成功 | IRQ编号可以移植到Z62，或真实传感器时序已恢复 |
| Image-bank compositor与supplied RAM layers | 可以合成已供应的层 | 合成层来自原固件自然捕获链 |
| Request-only processor/no execution provider | 能接收或保存请求，但执行实现仍缺 | 该处理器算法已经运行 |
| NVMe/BlockBackend | 明确挂载介质可提供存储后端 | 相机已经完成拍照编码、文件保存与回放 |

图明确标出三处未验证：自然scanout连接、自然显示生产者连接、原始capture/save连接。虚线很关键，不能把独立模块有功能当成整条成像链贯通。

## 3. Z62 本轮实现

r4已能在合法描述符上写合成RAW，但成功输出`raw-complete`没有连接sensor。保存的原固件样本显示，第二轮三次成功时：

- `20065504=0x8000`，mode2；
- `20065400=0x10011`，满足原模型mode2配置谓词；
- `2006550C=0xF3`，bit1掩码开启；
- RAW累计3次成功、27,427,584字节，之后仍35/3F。

r5增加独立的`functional-raw-completion`开关与`raw-dma-complete`输入：

```text
原固件提交 → r4严格描述符预检 → 四槽实际写入成功
  → 同engine raw-complete
  → r5开关开启 + mode2配置成立 + mask bit1开启
  → 20065508 bit1锁存 → 原sensor_update_irqs → IRQ92
```

这条映射依据Z62现有传感器mode2完成谓词，不是图中的IRQ94。它仍是**事务关联的功能性假设**，不能据此声称恢复了真实硅片时序。

### 实现约束

- 无时钟/周期成功源；失败DMA不发完成，仅写配置不发完成。
- 未arm/模式错误时拒绝，不在后来arm时补发过时事件。
- pending时合并，不伪造新边沿；W1C后下一笔成功事务可再次拉高。
- 仅同engine连接；主从计数与内存隔离。
- 原初始化one-shot不变，不直接补上层event8，不清错误。
- 与旧laboratory-frame-completion同时开启会拒绝，避免两个独立来源混淆。
- QOM只读source-events/completions/ignored/coalesced/last-reason，未知读数不变成0。
- reset与VMState subsection实现；live migration未实测。

设备源、固定输入SHA、三份manifest与构建命令详见 设备实施报告（本地证据，未分发：`analysis/z62-transaction-device/REPORT.md`）。
