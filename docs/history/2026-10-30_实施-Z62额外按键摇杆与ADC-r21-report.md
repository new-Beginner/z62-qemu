# Z6II 额外按键、独立摇杆与运行时ADC r21

当前检查点：四个GPIO按键、摇杆九种动作、独立ADC设备已实现和验证。模式盘原厂八挡观察仍在进行，不能把本报告作为完整机身、录像或刷写安全验收。

## Scope与方法

遵循用户完整机身目标与 研究范围（本地证据，未分发：`analysis/z62-body-r21/RESEARCH.md`），只操作原厂C1.70副本、独立QEMU和普通文件快照；不访问相机、USB/PTP或物理卡，不修改固件指令、返回值、输入报文或软件状态。

原件为ARM/Thumb裸固件，无宿主PE导入表；接口锚点是控制器GPIO、I2C扩展器、ADC和主处理器10436600输入解码。使用已有Ghidra11.4.2与原生QEMU/GDB追踪，原厂帧和报文字节保留。

## 实现与验证

- UI IDs26–29分别为AF-ON、Fn1、Fn2、录像键。新入口`start-z6ii-extra-controls.cmd`端口8678，保留普通键、双段快门及双拨轮。
- 原厂13秒观察严格出现四个独立GPIO和九种独立摇杆动作；输入报文均逐字节核对，释放归零，无额外中央误触发。该次使用冻结r13内核。
- 原版及候选的4GPIO、9摇杆、释放全部、非法位置拒绝、旧拨轮和双段快门均通过，正常退出。候选测试为原C1.70包走候选分支，健康unknown，不外推修改固件。
- Chrome确认四个按钮和独立九宫格可见，实点Fn2、右上、中央、释放，随后正常关闭；不是对焦点移动或录像功能验收。
- 新r21内核继承r18，SHA256为`0a772865868c4f666024533512d5ede2751255744caf56b594a41da6fc0ef90b`。24组在途ADC改值及19通道/边界/取消/复位通过；旧ADC/GPIO正负完成回归通过。旧r18不存在运行时属性的负对照保留。
- 6项新增输入队列测试通过。全量318项317通过，唯一旧slave调试端口就绪超时，单独复测9.680秒通过；不将原失败日志改成通过。随后3项硬件版本报告测试通过，实测r13/r18/r21标签分别正确。

## 失败与环境变化

首次extra-http在状态读取时超时，首次mode-selector在10.244客体秒后QMP超时且尚未发出挡位切换，两次均保留失败并关闭实例。随后发现系统Temp中的Ghidra、旧合成NOR和旧4GiB卡消失，原因未知，不推断超时与删除的因果关系。

已从校验存档恢复Ghidra到`<USERPROFILE>/Documents/Z62-QEMU-runtime`，并创建新的512MiB空白卡，SHA256为`a8a6ccc0129b962713931dc8ca130589ee2b0f12b551fb76cca69c7533a2a57f`；新NOR23为原定义零体+ENDM，hash保持`c7dd14358b45b2813fdee85fc587bcdd5899f7a81e0d5830513d631235bcc700`。新卡不冒充旧镜像。详细记录见 环境观察（本地证据，未分发：`analysis/z62-body-r21/environment-observations.md`）。

字段纠正：selector-resources首次记录的`mode_adc_channel_selector=18`实际是中断选择子，ADC通道由资源描述符offset0x0C给出2。旧字节证据保留，新工具字段更名为mode_adc_irq_selector。
