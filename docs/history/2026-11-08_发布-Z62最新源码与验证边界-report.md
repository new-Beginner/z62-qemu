# Z62 QEMU 最新源码发布与验证边界

源码快照：**2026.11.08-r110-fenestra-r19**。这是研究平台，不是完整相机、完整 Fenestra SDK 或可刷固件；默认交互仍 r75／内核 r69，新 CW 模型保持显式开关。r20 目前只有范围检查，没有可交付 SDK 实现。

## 开发了什么，能验证什么

| 功能 | 可以验证 | 不能据此证明 |
|---|---|---|
| 原厂／候选 C1.70 加载、ARM/Thumb 执行、LCD 菜单 | 容器布局与 CRC、部分启动路径、菜单分支及实际屏幕变化 | 完整启动、所有配置兼容、真机升级与断电安全 |
| 双段快门、拨轮、模式、ISO、AF-ON/Fn、摇杆等输入 | GPIO/ADC 输入到达及部分原厂应用响应 | 输入到达不等于合焦、摄影或录像完成 |
| RAW、DMA、中断、有限／连续统计、受限软件 ISP | 指定配方下的真实客体内存写入、数值独立重算、ACK、背压、取消和复位 | 完整传感器、硅片时序、物理测光/PDAF 或全分辨率 ISP 等价 |
| 场景／曝光／手动镜头、软件 JPEG/实验 NEF／短 MP4、虚拟存储 | 输入图像响应、来源帧、软件编码解码、保存回放删除及持久化边界 | 原厂镜头协议/AF、原厂编码存入客体 SD/DCIM；目录卡与原厂卡链不同 |

| Fenestra ARM32 loader-only | 无 Nikon 固件夹具下格式检查、复制重定位、Thumb 回调和负例拒绝；原厂任务/队列的局部观察 | 已接入原厂、完整 SDK、卡载插件、原厂模块菜单或安全刷机 |

软件照片当前 JPEG 640×424、实验 NEF 1514×1006（12 有效位）；软件视频 640×424、VFR、静音。不能当作原厂全画幅影像能力。详细证据入口见[项目说明](../../README.md)、[能力覆盖表](../CAPABILITY-COVERAGE.md)、[Fenestra阶段合同](../profiles/README-FENESTRA-Z62.md)。

## 最新诊断的证据链

- **证据：**r105–r109 独立观察与验证记录、r110 `publication-verification-20261108-1/result.json`。**发现：**原厂 APPLV 已运行，局部转换和参数查询分支可核对，但菜单返回后仍无完整采集恢复证据。**路径：**`analysis/z62-request-qualification-r110/`；公开副本提供精选摘要，不提供完整 RAM 或原始大轨迹。
- **证据：**Fenestra r17 联合链、r18 业务前缀与 r19 队列离线复核。**发现：**同次创建/启动/BX及局部内层返回可成立，但 r18 整跑触界失败，r19 不追认旧 pending，也不证明业务完成或所有权。**路径：**`analysis/fenestra-z62-task-chain-r17/`、`analysis/fenestra-z62-business-r18/`、`analysis/fenestra-z62-queue-r19/`。
- **证据：**`fenestra/z62/PORT.json` 与加载器验证。**发现：**阶段仍为 `experimental-loader-only`，原厂集成/刷机/真机门槛关闭。**路径：**[Fenestra说明](../profiles/README-FENESTRA-Z62.md)。

本轮发布检查只验证公开源码、清单、文档链接、无固件测试与选定 C 核心；不把已有历史实验计数冒充本轮重跑，不访问相机、不启动固件、不刷机。实际检查命令与结果由公开 `docs/VALIDATION.md` 记录。
