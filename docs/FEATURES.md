# 功能清单与验收边界

当前源码快照为**r103**，默认仍r75界面／r69内核。r103默认off的C统计输入桥让两个已定位的原始800h停止等待自然成功；16秒／24秒原厂窗口均状态[]，拍摄OSD恢复。背景仍绿色、preview0，完整原厂取景／摄影／AF及刷机安全未通过。下方r98及更早条目保留历史范围。

| 本次r99–r103 | 实际实现或证据 | 限制 |
|---|---|---|
| r99／r100 | 原厂scalar消费者、3F追加及停止返回80h／mode清理0的真实配对 | 当时只定位失败，未修复 |
| r101 | 直接kernel结果0／FFCE0000h，mode2／mask就绪但数据源0 | 不能靠补IRQ／ready代替数据 |
| r102 | 完整2020×136 C内联读出与数据完成；原厂288次、数值审计通过 | 来源在失败后才开放；当时仍Error |
| r103 | 完成图像→30×12／61槽统计DMA；pending／cache／batch分开，缺源不回用CW | C均值非测光／PDAF；每batch保留一幅图像，不是61个新RAW |
| r103原厂恢复 | 两个kernel0／BOOL1及原厂store；24秒CW541、grid322、原厂scalar独立重算 | 两次取数暂停，绿色背景、preview0；[合同](../qemu/z62-capturework/READOUT-STATISTICS-CONTRACT.md) |

当前更新至 2026-11-04/r98，默认运行组合仍为 r69 内核／r75 界面。A=原厂执行，B=有证据的设备行为，C=软件替代，D=未实现/未验收。这里的“通过”均带版本和范围，不能读成整机通过；当前细项以 [覆盖表](CAPABILITY-COVERAGE.md) 为准。r98 两批有限采样后原厂进入 Error，预览0，不能保证候选固件可安全刷机。

| r49之后新增 | 当前证据 | 未完成 |
|---|---|---|
| r69实际提交来源、r75界面 | 有来源的C照片；r74 API照片回放/2×缩放/删除及r75参数草稿同步通过 | 原厂编码、客体DCIM和模式完整往返仍缺 |
| r73工作目录存储、r74永久故障保存 | 临时/缓存/会话位于工作目录，故障文件不随VM scratch清理 | 真实自发QMP故障根因未知，原生故障注入不冒充自然故障修复 |
| r83–r85真实内核事件 | 原厂0→00800000h store、setter返回0、AND等待原始FFCE0000h；失败/恢复分别保留 | 其它输入引擎就绪生产条件及模式恢复仍未补齐 |
| r86–r88 独立数值与来源原语 | 两级有理缩小、CFA、LUT、RAW12/14/16；MAIN／linear16／CRC／单缓存生命周期；冻结 transfer 量化重建 | C 模型；LUT8 重建是区间及中点，非无损逆变换 |
| r89 独立 QEMU 采集后端 | 有限 RAW12 配方、实际配置提交、冻结 LUT、单 worker、代次取消、bank/ring；DMA 有效行写完后事件 3/4/135、W1C 背压 | 默认关闭；没有全部 ISP、完整迁移或所有 inflight 取消竞态验收 |
| r91 原厂 MAIN 交付 | 显式策略接受已观察 `0x200040`；原始 C1.70 窗口 13 次 DMA、13 组 CPU ACK；6 帧 9,138,504 样本独立核对一致 | 统计／预览为 0、LCD 全黑；物理源对和高层完成未实现；[详细说明](profiles/README-Z62-CAPTUREWORK-DEVICE.md) |
| r92 CW到连续统计 | 真实CW DMA后冻结量化linear12供五路统计；原生157,440字节重算，原厂13帧／2批和CPU ACK | 原厂五路数值没有另存，不等价全部ISP |
| r93–r95采集组与参数 | 三类真实DMA后事件96；资源39标签追踪，+3Eh系数更正；显式参考输入下group13次／ACK13次，216个原厂已分类字节核对 | C曲线／FIR非工厂标定、非PDAF；完整缓存不是输入整块镜像 |
| r96/r97原始等待与连续供帧 | 慢源2成功1超时；实际时钟MAIN后三个AND等待全成功，32个accepted包可重构 | 断点扰动；不积压补帧、不把accepted当DMA，整机功能未过 |
| r98保留帧有限统计 | 停采保留、batch冻结、下一请求latest；原厂122采样／2批／0拒绝；原生93,696B、原厂两份1,536B重算一致 | 同一保留帧，非122次新RAW；16秒终态Error、preview0，默认关闭；[合同](../qemu/z62-capturework/FINITE-CONTRACT.md) |

## 机身交互

按钮“输入通过”和“应用功能通过”分开。页面来自原厂 LCD；软件媒体/场景控件明确是 C 层。

| 控件 | 已覆盖 | 应用层边界 |
|---|---|---|
| MENU、方向、OK、半按返回 | 原厂输入、选中条变化、部分菜单往返 | 非所有模式/设置/长稳均验收 |
| 快门半按/全按/释放 | 两段耦合、启动释放、原厂报文与相应电气边沿 | 原厂曝光/编码/客体存卡仍缺；软件拍照走独立 C 后端 |

| 模式盘 | 八挡输入及有限原厂显示 | P/S/A/M 的全部曝光行为、用户设置和机械锁细节未全验收 |

## 验收判断

已完成的局部测试和 C 层媒体让平台可用于研究部分候选行为；仍不能完成“开机→原厂曝光与 AF→原厂拍摄编码→客体存卡→原厂回放→关机”的完整验收。

后续按 [技术难点](TECHNICAL-CHALLENGES.md) 和 [开发过程](DEVELOPMENT.md) 继续。详细历史清单在 [CAPABILITY-COVERAGE](CAPABILITY-COVERAGE.md)，当前失败证据在 [r49 报告](history/2026-11-02_验证-Z62模式恢复与视频配置缺口r49-report.md)。
