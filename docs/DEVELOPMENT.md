# 开发过程与完整报告索引

当前更新至 2026-11-03/r85。前一公开快照止于 r49；下表较早条目保留历史范围。代码从本地工作区导入；原 Git 历史只保存了早期基线，之后主要通过冻结源码、独立构建、实验目录和阶段报告保存。本次保留已有公开 Git 历史，不伪造逐日提交，也不把观察编号理解为新内核构建次数。

本地适配编号、上游 Z62 R3、宿主版本和内核版本不同：r27 宿主使用 r24 内核，r49 是运行在 r48 上的观察工具。历史报告保留当时结论，当前状态以 [功能清单](FEATURES.md) 和 [限制](LIMITATIONS.md) 为准。

## 目标与开发方法

先完善可交互相机：机身操作、虚拟场景/镜头、照片生成存卡回放、视频，再建立原厂 AF 多帧回放与镜头反馈。当前没有替写、设计或优化 AF。

采用明确的 C 级软件 ISP/媒体后端推进数据链，同时保留原厂指令执行。每次证明“有效配置→真实输入→运算→写回→IRQ→原厂消费”，不用改 ready、清队列、加成功返回或缩短超时来宣称完成。新设备使用独立内核与 manifest，失败和旧版本保留。

## 必须保留的教训

- 图片、空错误列表、卡初始化和同步返回不是整机验收；取消回收也不是像素处理。
- 输入命名、默认全按、过早按键、Thumb/ARM/TBB/PIC/尾调用、错误栈帧，都可能污染结论。
- 同地址复用、单指令多观察点、QMP 超时后的分片/迟到回复，需要工具自身验证。
- 未变的失败输出不是收到事件；命令81和单元结果82不是可互换的“完成”。
- 缺日志、窗口末尾未返回、预算中止、格式不支持、错误假设及失败源码都保留。
- 每项新设备均需实际数值和写回、异常路径，再由原厂消费；不改原厂成功状态。
